# Classifier · 文献研究工作台

面向跨学科科研人群，帮助研究者围绕研究问题收集和理解文献、比较证据，形成可追溯、可持续更新的研究成果。项目源自 LocalLens 的论文研究模块，向独立的文献研究产品发展。

**当前已实现 M1 文献组织、M2 阅读笔记、M3 多文献比较与 M4 研究成果**。可以围绕研究主题整理资料、保存笔记、比较证据，并形成可编辑和导出的研究总结。笔记、比较表与成果均保留证据快照和历史版本。原有本地 OCR、表格、Word 公式和 PDF 页图核对继续可用。

产品主线为“研究主题 → 文献研读 → 证据比较 → 研究成果”。定位见 [产品框架与路线图](docs/product-framework.md)，阶段实现与验收见 [M1](docs/m1-implementation.md)、[M2](docs/m2-implementation.md)、[M3](docs/m3-implementation.md) 和 [M4](docs/m4-implementation.md)。

当前支持本机 Web 开发运行，Electron Mac x64 测试包已完成 D0 本机验收和 S0 存储验证，D1 数据安全正在实施；尚未正式发布。Windows x64 与 Mac ARM 暂缓，最低系统／配置和干净机器验证保留在发布阶段。实际状态见 [D1 实施记录](docs/d1-implementation.md)，发布顺序见 [桌面交付方案](docs/desktop-release-plan.md)。

当前进度与遗留任务统一维护在 [工作清单](docs/work-items.md)；进入桌面阶段前的实现与验收范围见 [M4 收尾基线](docs/m4-closeout.md)。

## Web 开发启动

需要 Node.js 22.13+（建议 Node.js 24 LTS）。在本目录运行：

```sh
npm ci
npm start
```

扫描件 OCR 需要另外安装 Tesseract 和语言包，macOS 可运行 `brew install tesseract tesseract-lang`；本机已安装。

打开 <http://127.0.0.1:8790>。无需配置模型即可导入文档和检索原文。

使用流程：创建研究主题并填写研究问题 → 关联已有文献或导入新资料 → 在“筛选与阅读记录”中保存决定和进度 → 打开研读并核对原文。同一文献可以关联多个主题，书目信息共享，筛选与阅读状态按主题分别保存。“全部文献”可直接打开原有资料；刷新页面会恢复最近的主题或文献位置。

**AI 研究任务入口**：点击右上角“模型连接”，填写服务商的完整 Chat Completions 地址、模型名称和 API Key，启用本次连接；在主题中选择 2–12 篇文献，用一句话说明比较目标并开始。AI 建议 1–6 个维度，逐项检索相关节选，生成带出处的整份比较草稿。核对后点击“采用比较草稿”，再点击“生成研究总结”，审阅并采用总结后即可编辑和导出 Markdown。无需预先填写笔记、逐格填写比较表或再次选择总结材料。后续要求可填写在比较页，如“增加样本量，重点比较方法”；当前会重新生成整份提案，采用前原内容不变。

整份比较任务显示进度、支持停止与重试；生成期间的人工修改、来源版本或范围变化会阻止旧草稿覆盖。维度规划使用标题和有限开头节选，比较使用检索得到的部分证据，不代表通读全文；“未找到”不代表论文未报告。详情与验证范围见 [UX-02 实施记录](docs/ux-02-implementation.md)。

研读界面左侧可切换“文档问答”和“阅读笔记”。点击原文或回答旁的“记入笔记”，选择通用或自定义字段，修改内容后保存；点击笔记的“出处”查看保存时的原文，并定位回文献。笔记按主题与文献分别保存，移出主题后仍可从主题笔记中打开。未保存的输入按笔记与编辑会话分别保留，可从草稿列表选择“继续草稿”；保存一条笔记不会清除其他标签页的草稿。版本冲突时会保留当前输入。

主题中的“多文献比较”可新建比较表，选择 2–12 篇文献及 1–12 个维度。每格可从笔记填入、关联原文或手工记录，并填写适用条件与不可比原因。“跨文献判断”保存共同点、差异、冲突或材料不足的说明。点击出处可回查原文并返回比较表；移除行后，历史引用仍可定位到版本未变的原文。当前标签页的未保存编辑在刷新后可继续；对应维度或文献被移除时，草稿仍保留并可查看、复制。

配置模型后，可按列生成比较建议。建议只使用所选文献提供的原文，需审阅后点击“采用本列建议”才会更新表格；生成期间的人工修改、来源变化或范围调整会阻止旧建议覆盖。模型校验保证来源身份和结构符合约定，具体判断仍需人工核对。

默认中文维度支持中英文关键词和章节检索。检索只读取部分原文；补充上下文不表示已经找到所需信息。自定义维度按名称和说明检索，可在说明中补充英文关键词。

主题中的“研究成果”可新建总结，选择笔记、比较表或原文片段，点击“将所选材料加入正文”开始整理，也可以手工添加段落。编辑章节、判断类型和引用后保存，逐段核对出处；支持草稿恢复、历史恢复及归档。“导出 Markdown”保留书目信息、原文摘录与页码或段落定位。材料更新不会改写已引用的旧摘录。

重复加入相同材料会跳过已整理的条目，保留人工修订；材料内容变化后只追加变化的条目，删除的材料段落可以重新加入。

配置模型后可生成研究草稿。先审阅，再明确采用以替换正文，原版本保留；成果或来源有新变化时拒绝旧草稿。模型只阅读所选材料，引用身份有效不代表判断必然成立。

“模型连接”只保存在当前后端进程内存中，桌面完全退出后需重新连接；不会把密钥写入资料库或浏览器存储。更换／清除连接影响新任务，正在运行的任务保留启动时配置，可在任务页停止。尚无连接测试和系统凭据保存。本机 HTTP 服务只允许回环地址，其他接口使用 HTTPS；暂需非空 API Key，无认证的本地服务可填服务允许的占位值。

Web 开发也可以将 `.env.example` 复制为 `.env`，填写模型服务提供的完整 Chat Completions 地址、API Key 和模型名称，然后重启服务：

```dotenv
CLASSIFIER_MODEL_API_URL=https://your-provider.example/v1/chat/completions
CLASSIFIER_MODEL_API_KEY=your-key
CLASSIFIER_MODEL=your-model
```

文档问答模型须支持 function tools；比较和总结要求模型按提示输出 JSON。密钥只保留在服务端；发起相应 AI 任务时，问题、相关文档片段和所选笔记／比较材料会发送给所配置的模型服务。问答在未配置模型、调用失败或引用校验失败时展示原文检索结果。

## 当前原型能力与边界

- 研究主题创建与编辑、研究范围、文献关联与移出、主题内筛选和阅读状态、相关性与筛选理由。移出主题保留原文件和其他主题的关联。
- 手工维护标题、作者、年份、期刊／会议、DOI 和来源链接；修改同步到所有关联主题。导入可指定目标主题，后台完成后自动保存关联。
- 结构化笔记支持研究问题、材料或对象、方法、主要发现、局限、待验证问题及自定义字段；区分原文报告、模型归纳和用户判断，以及未报告、不适用、未找到等状态。
- 引用保存原文与定位快照。笔记内容或证据修改后重新标记待核对；解析内容变化时保留旧原文并阻止错误定位。支持版本记录、恢复为新版本、归档和恢复。
- 配置问答模型后，可按字段生成笔记建议。建议经用户选择才保存为新笔记，再次生成不会覆盖已有人工修改；任务支持取消及重启中断提示。
- 多文献比较表、可编辑维度、笔记／原文取值、缺失信息与可比性状态、跨文献判断、历史版本及归档。来源笔记或原文变化时提示复核，已保存比较内容保持其原快照。
- 研究成果按段落编辑，区分原文报告、模型归纳、用户判断与待验证问题；保留材料快照、引用、核对状态与版本，可导出 Markdown。模型草稿须显式采用。
- PDF、DOCX、Markdown、TXT、HTML 文件导入；单文件最多 25 MB，PDF 最多 500 页，提取文本最多 200 万字符。
- 原文件保存、文献列表、中英文关键词检索、单篇问答、引用跳转和问答记录。
- PDF 按页及坐标定位，支持页图高亮核对；本地 Tesseract 识别扫描文字。支持表格行列和规则合并单元格、DOCX 原生公式转 LaTeX。PDF / 扫描公式保留字符和页图，复杂数学结构仍需核对。参见 [复杂文档解析](docs/document-parsing.md)。
- 导入使用后台任务，显示页码进度，可取消；支持自动识别或全页 OCR。已有文档需重新导入才能获得新的结构信息。
- 回答区分原文事实和归纳判断。引用校验保证 ID 属于当前任务读取过的片段，**不保证模型判断必然被该片段支持**，研究结论仍需对照原文核验。
- 问答可取消，90 秒超时，最多 8 次工具调用；重启后未完成任务标记为中断，可重新提问。
- Web 开发默认使用 `data/`，桌面使用系统应用用户数据目录。既有 JSON 资料库继续可用，显式迁移后的资料库使用 SQLite；启动不自动迁移。目录锁禁止两个服务同时打开同一资料库。目前面向本机单用户，未提供账号、共享权限或公网部署能力。
- 保留 `CLASSIFIER_HOST=127.0.0.1` 等回环监听；不要直接绑定 `0.0.0.0`、`::` 或局域网／公网地址。Origin 校验不是身份验证，能访问服务的人可以读取和修改资料。
- 原文件、任务结果、导入记录与历史版本长期保留，目前没有自动清理或按条删除入口；归档不会释放磁盘空间。已有显式离线目录备份／校验／恢复／迁移工具，先停止服务，再按 [D1 工具说明](docs/d1-implementation.md#显式离线工具) 操作；恢复到新目录，不覆盖现有资料。桌面入口、ZIP 和完整崩溃恢复仍待完成，不单独复制活动 SQLite 主文件或删除历史文件。
- PDF 页图同一时刻渲染一张；快速翻页或多个标签页请求时可能提示暂时无法读取，可稍后重新打开当前页。
- 暂未包含 URL 导入、自由形式的跨文献问答、Word／PDF 成果导出、DOI 自动补全、语义向量检索或模型训练。

## 项目结构

```text
apps/api/src/   HTTP API、主题与文献组织、文档解析、检索、Agent 和任务存储
apps/web/       科研文献工作台
tests/         检索、Agent 引用约束、文档解析、HTTP 与浏览器流程测试
docs/          API 约定与产品架构
data/          本地主题、文档、笔记、比较表、研究成果与历史、原文件和任务（不纳入 Git）
```

运行 `npm test` 验证基础流程。HTTP 测试会临时监听本机随机端口，并使用独立临时数据目录；不调用真实模型。

浏览器测试同样使用独立临时目录，覆盖 M1–M4 流程、服务重启、手机宽度、后台导入、编辑冲突、引用版本变化、模型建议采用与 Markdown 下载：

```sh
npx playwright install chromium
npm run test:e2e
```

已有 Google Chrome 时也可以运行 `CLASSIFIER_BROWSER_CHANNEL=chrome npm run test:e2e`。结果保存在 `test-results/`，不纳入 Git。

桌面业务回归使用 `npm run test:desktop:business`。为同一组业务测试指定 `CLASSIFIER_TEST_STORAGE=sqlite`，会先将每个隔离 JSON 测试库显式迁移到 SQLite，再运行完整流程；结果单独保存在带 `-sqlite` 后缀的目录。`npm run test:storage` 验证桌面运行时下的存储故障原型与生产维护流程，使用 `CLASSIFIER_PACKAGED_EXECUTABLE` 可指定真实测试包。以上测试不调用真实模型，也不使用用户资料。

桌面开发使用 `npm run desktop:dev`，打包与 OCR 资源准备见 [D0 实施记录](docs/d0-implementation.md#自动化入口)。桌面不自动读取仓库 `.env`，可用“模型连接”启用本次会话；系统凭据保存、连接测试和撤销授权仍属于 D3。

参见 [产品框架与路线图](docs/product-framework.md)、[API 约定](docs/api.md) 和 [产品与架构边界](docs/product-boundary.md)。
