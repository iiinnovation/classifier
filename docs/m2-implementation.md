# M2：阅读笔记与证据

状态：2026-10-08 已完成并验证。

范围：落实产品框架的 M2。以“主题＋文献”为笔记归属，完成创建、结构化整理、人工修订、出处核对、保存与恢复。模型建议经用户采用才成为笔记，后续生成不覆盖已有笔记。

## 数据与接口设计

- 每条笔记独立存储在 `data/notes/<id>.json`，含主题、文献、字段名称、内容、内容状态、判断类型、来源、证据快照、人工核对状态、版本号、编辑历史和归档状态。
- 通用字段为研究问题、材料或对象、方法、主要发现、局限、待验证问题；允许自由命名。没有记录的字段显示未记录；保存时可明确标记已记录、未报告、不适用或未找到。
- 判断类型区分原文报告、模型归纳、用户判断。模型归纳只能来自已完成的模型回答；用户修订后保留生成来源并标记人工修改。
- 证据由服务端从当前原文或已完成问答中取出，保存文献 ID、片段 ID、解析内容指纹、原文及定位快照。指纹不受书目信息编辑影响。解析内容变化或旧问答没有版本信息时，显示保存的原文并标记待重新核对，避免错误跳转。
- 每次编辑递增版本，保存旧版本；更新携带预期版本，冲突返回 409。内容或证据变化后重新标记待核对。归档可恢复，历史版本可以作为一个新版本恢复。
- 新笔记要求文献已关联主题；移出关联后仍可访问、编辑和核对既有笔记。再次关联不会清空笔记。

接口：

| 接口 | 行为 |
| --- | --- |
| `GET /api/topics/:topicId/notes` | 主题笔记，含已移出主题文献的保留记录 |
| `GET /api/topics/:topicId/documents/:documentId/notes` | 当前文献笔记、关联状态和最近笔记建议任务 |
| `POST /api/topics/:topicId/documents/:documentId/notes` | 创建笔记；浏览器提供固定请求 ID，重试不重复创建 |
| `GET /api/notes/:id` | 笔记及历史版本 |
| `PATCH /api/notes/:id` | 按版本编辑、人工核对、归档或恢复历史版本 |
| `POST /api/topics/:topicId/documents/:documentId/note-suggestions` | 针对指定字段创建模型建议任务，复用问答超时、取消和重启中断机制 |

## 工作台

单篇研读左侧切换问答与阅读笔记，右侧保留原文。原文、PDF 引用片段及问答结论均可记入笔记。编辑器可调整字段、内容、判断类型、内容状态与引用；草稿按笔记与编辑会话分别保留，列表支持选择继续或清除。刷新优先恢复当前标签页的草稿，旧单草稿格式仍可读取。主题概览汇总笔记，提供返回原文入口。

笔记中的出处先展示保存的原文；版本一致时允许定位当前原文。人工核对完成需要单独操作。缺少模型时保留手工笔记与引用保存功能。

## 验收

1. 从原文与问答引用创建笔记，准确保存归属、来源和出处。
2. 调整通用字段、自定义字段、缺失状态和内容；刷新、重启后保留修改。
3. 同一文献在不同主题下的笔记互不混淆；移出关联后保留既有笔记。
4. 检查版本冲突、重试幂等、编辑历史、归档恢复与人工核对状态。
5. 修改书目信息保持引用有效；解析变化与重新导入不会误指向新片段。
6. 模型建议能采用、取消与再次生成；新建议不覆盖人工修改，未配置或失败时说明状态。
7. 运行旧有回归、M2 HTTP 与浏览器流程；用真实论文验证保存、修订和出处核对，并检查桌面与手机布局。

## 验收结果

运行环境：Node.js 24.12.0、macOS、Google Chrome。全部测试使用临时数据目录；模型相关测试使用受控响应验证流程，不调用真实模型供应商。

| 验收项 | 结果 |
| --- | --- |
| 原文与问答引用保存 | HTTP 与浏览器通过，保留所属文献、来源和原文片段 |
| 通用／自定义字段与缺失状态 | 通过，可保存空的未报告记录及自定义研究字段 |
| 编辑、草稿、冲突与重启 | 通过，过期修改不会覆盖新版本，草稿保留输入并重新核对引用版本 |
| 历史、人工核对与归档 | 通过，修改后重新待核对，历史恢复创建新版本，归档可取消 |
| 多主题与移出关联 | 通过，同文献笔记按主题分别保存，移出后仍可打开与编辑 |
| 引用与解析版本 | 通过，书目编辑不失效；重新解析保留旧快照；重新导入获得新文献 ID |
| 模型建议 | 通过，采用才新建笔记，再次生成保留人工修订，支持取消及中断状态 |
| 桌面与手机布局 | 1440px 与 390px 浏览器和截图核对通过 |

命令：`npm test` **32 项通过**；浏览器回归共 **22 条通过**（原有 14 条与本轮新增 8 条恢复用例）。完整入口为 `CLASSIFIER_BROWSER_CHANNEL=chrome npm run test:e2e`。测试见 [笔记 HTTP 测试](../tests/notes.test.mjs)、[笔记浏览器流程](../tests/e2e/notes.spec.mjs) 和 [笔记恢复回归](../tests/e2e/notes-recovery.spec.mjs)。

## 代码审查修复

| 已复现问题 | 修复与验证 |
| --- | --- |
| 迟到的“载入已保存版本”响应，把另一主题的笔记写进当前编辑器 | 捕获发起时的编辑器和导航版本；关闭、切换或继续输入后忽略旧响应，且校验返回记录归属 |
| 多标签页共用草稿键，保存一条笔记清掉另一份草稿 | 草稿按笔记、编辑会话独立保存，标记标签页归属；仅清理本次草稿，恢复时不覆盖其他标签页的内容 |
| 新建已落库但响应丢失，修订草稿反复提交创建并陷入 409 | 尝试确认已创建记录，保留修订并转为按版本编辑；查询暂时失败时，刷新后的已保存列表也能识别原创建版本。并发新版本仍触发冲突保护 |
| 文献切换失败后，旧文献仍显示但其笔记被清空禁用 | 获取新文献成功后才切换笔记上下文，失败时保留原文献的笔记与编辑入口 |

新增恢复测试还覆盖：同笔记双标签页、加载版本期间继续输入、查询创建结果失败后刷新恢复，以及旧草稿格式迁移。
