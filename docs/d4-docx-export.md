## 使用与导出内容

在研究成果页点击“导出 Word”，下载 `.docx`；“更多”中保留“导出 Markdown”。两者只导出请求时指定的当前已保存版本。未保存的编辑、未采用的模型草稿不会进入文件；空正文及版本不一致返回 409，不会下载空成果或悄悄切换版本。

文件包含标题、研究问题、成果版本和保存时间；按章节排列正文，保留判断类型、核对状态与条件说明。原文引用按正文首次出现顺序编号，Word 中的编号可跳转到文件末尾的出处，保留书目信息、DOI／来源链接、摘录、文件身份、解析版本及 PDF 原文页码或段落位置。PDF 页码指所引用的原文件页码，不随 Word 重新排版改变。

材料或原文变化、缺失、损坏、已删除时继续使用保存的摘录，并保留状态与复核提示。下载不增加成果版本或修改研究记录。引用编号是当前导出快照中的编号；后续在办公软件编辑时不会自动调用文献管理器重新编号。

Word 和 Markdown 共用独立的结构化导出表示，分别处理各自的文字转义，不反解析 Markdown。DOCX 使用普通段落、章节样式、内部书签和引用链接，A4、1 英寸页边距，中文字体配置为宋体，拉丁字体为 Calibri；未嵌入字体，实际字体取决于办公软件环境。原文中的 HTML、图片语法、URL 等按文字保留，不生成远程资源或宏。XML 无法表达的控制字符／孤立代理字符替换为 `�`。公式保留已有文字，不转换成 Word 原生公式；尚无 PDF 成果导出或比较矩阵的 Word 网格导出。

## API 与实现

- `GET /api/reports/:id/export?revision=N&format=docx`：Word MIME 类型与 `.docx` 附件文件名。
- `format=markdown` 或省略格式：保留既有 Markdown API。
- 其他格式返回 422；两种格式沿用当前版本和非空已保存正文检查。

附件文件名按 Unicode 字符截取，替换路径／控制字符及常见非法文件名字符；使用 UTF-8 `Content-Disposition`，避免截断表情的代理对。桌面协议桥直接传递二进制正文和附件头。

实现位于 `apps/api/src/report-export.mjs`（共同表示与 Markdown）、`report-docx.mjs`（DOCX）、`reports.mjs`／`server.mjs`（版本与下载），以及 `apps/web/reports.js`／`index.html`（入口与下载）。复用已有 JSZip，没有新增依赖。
