# D1 兼容备份恢复与迁移准备重建

日期：2026-10-25。本轮补齐 D1-05 的启动失败恢复入口，以及 D1-02 的迁移准备失败处理。原库、升级前备份和旧暂存目录均保留。

2026-10-26 补验：当前保留的 Mac x64 包已登记为 [预览回退基线](rollback-baseline.json)，6 个未来格式恢复样本通过，包含备份后修改、运行中任务及未知目录保留。用 `node tools/verify-rollback-baseline.mjs` 核对本地包及归档报告；样本不等于实际发行版本对通过。详情与复跑见 [满盘／回退基线](d1-full-volume.md)。

## 未知格式与启动恢复

业务启动先检查资料库清单；未知格式、未完成迁移、清单超过 64 KiB、清单不是普通文件或清单缺失但数据库存在时拒绝打开。拒绝发生在业务记录扫描、任务中断更新及 SQLite 日志表升级之前。目录排他锁仍按原机制创建和释放，不把辅助锁文件变化描述为整个目录逐字节只读。

后端无法启动时，“资料库未能打开”对话框提供退出、检查清单、保全原件和“从兼容备份恢复”。用户可选择目录或 ZIP 备份；应用先在隔离副本中核验文件与记录，再展示备份时点、格式、版本和数据回退含义。没有兼容备份时使用支持原库格式的应用版本，不将未知格式自动转换成旧格式。

确认后再次核对备份 revision，持有原目录锁，复制并校验当前已知研究文件、数据库及辅助文件作为保全副本，然后恢复到新的 `libraries/<uuid>`。只有新后端启动和位置保存成功后才进入工作台。原库中的备份后修改不合并，仍保留在原库和已知研究文件的保全副本中。未知新版格式可能使用额外目录，这些目录继续留在原库，不声明旧版能识别或完整复制未知结构。

备份变化、保全失败、恢复失败、目标启动或位置写入失败时保持原位置，保留已生成副本并回到恢复选择流程；不会反复尝试启动已知不可读的原库，也不会创建空库替代它。退出会等待在途恢复完成并停止后端。

这项防护适用于包含当前格式检查的应用构建。已经分发的早期 D0 二进制无法通过更新文档获得新防护，不能让它直接打开新版 SQLite 或未来格式目录；应使用有格式防护的兼容构建，并从升级前备份恢复到新目录。

## 迁移准备失败

`prepare-migration` 先生成验证后的 JSON 备份，再写迁移布局、批次身份、数据库和进度事务。备份完成后的失败信息包含备份位置与暂存目录；进度通知也包含这些路径。

已建立完整进度表的批次继续使用原来的“查看迁移进度或继续迁移”。对于数据库或进度表尚未完成的批次，不在旧暂存目录猜测修复；使用“从升级前备份重新准备迁移…”，选择已验证的 JSON 目录备份，先备份当前库，再从同一固定时点创建新批次并迁移。旧暂存目录不删除、不改写。来源库在中断后产生的修改不混入旧快照，在原库及切换前备份中保留。

离线命令：

```sh
node tools/storage-maintenance.mjs prepare-from-backup /path/to/pre-upgrade-json-backup /path/to/new-sqlite-library
node tools/storage-maintenance.mjs resume-migration /path/to/new-sqlite-library.partial-MIGRATION_ID
```

第一个命令返回实际 `stage`，第二个命令用该路径继续。目标父目录必须存在，目标目录须尚不存在。新批次的来源记录为所选备份目录；不将其描述为自动合并原工作库。

## 验证范围

Node 覆盖 JSON／SQLite × 目录／ZIP 的兼容恢复、未知格式拒写、队列状态不变、原件保全、备份确认后变化、并发目录锁、取消／退出以及目标启动／位置保存失败。迁移准备在备份完成、布局发布、批次身份发布、数据库建表和准备完成五处通过真实 SIGKILL 验证，再从同一备份重建，核对旧暂存字节和备份后来源修改。

完整 Node **246/246**、最终包桌面 **18/18**、存储 **5/5** 通过，62 个应用文件与包内源码逐字节一致。最终源码、安装包运行结果与哈希见 [验证记录](measurements/d1-compatibility-mac-x64-2026-10-25/validation.json)。桌面测试使用受控原生对话框选择，调用打包生产模块和真实 utility 后端；不等于已对每个历史发行包实施二进制回退验证。真实断电、物理磁盘故障、最低配置、干净机器和延期平台仍保留验收项。
