# M4 收尾基线

日期：2026-10-09。范围：M3 提交 `e468992` 之后的研究成果实现、两轮代码审查处理，以及桌面交付规划归档。本文件与实现、测试、统一清单一起构成 M4 收尾提交；该提交是进入 D0 前的代码回退点。

## 已交付能力

- 从笔记、比较表与原文片段组织研究成果，编辑章节、正文、判断类型与引用。
- 证据快照、派生复核状态、版本冲突、历史恢复、草稿恢复及归档。
- 模型草稿先审阅再采用，保护已保存的人工修改和变化后的来源。
- Markdown 导出，保留文献身份、书目信息、原文摘录及位置。
- 审查修复：大成果请求容量、原文材料草稿显示、编辑中回查原文、材料追加去重、旧成果兼容、笔记文献前缀与显式可信来源校验。

详细行为和限制见 [M4 实现说明](m4-implementation.md)；接口见 [API 约定](api.md)。

## 遗留工作的去向

此前确认的 M4 缺陷已经修复并纳入回归。正式桌面交付、数据删除／迁移／备份恢复、真实模型和跨学科质量验收仍未完成，其状态统一记录在 [工作清单](work-items.md)，不因 M4 功能完成而被视为发布通过。

已采纳的执行方向为 Electron、稳定应用来源与受保护的回环 HTTP、单主窗口；SQLite 为默认存储目标，须经 S0 验证。架构取舍与资源门槛见 [桌面交付方案](desktop-release-plan.md)，原始评审与事实修正见 [整体代码评审](review-m1-m4-2026-10-09.md) 和 [桌面方案评审](review-desktop-plan-2026-10-09.md)。

执行顺序：**M4 收尾 → D0 → S0 → D1 → D2 → D3 → D4 → D5**。首个后续任务是 D0-01 的目标平台、运行时和验证矩阵，不重做 M1–M4。

## 回退边界

该基线固定代码和文档，**不包含用户数据备份**。后续代码回退不能替代数据恢复；涉及格式变更时，必须使用 D1 定义的兼容检查及备份恢复路径，不能直接用旧程序写入较新的数据目录。
