# 桌面交付方案第二轮评审处理

日期：2026-10-09。来源：用户转交的方案评审。本文记录意见及处理决定；执行依据为修订后的 [桌面交付方案](desktop-release-plan.md)。本轮只调整规划并进行只读核查／内存数据库探测，未实施桌面壳或存储迁移。

后续各项实施状态见 [统一工作清单](work-items.md)；本文作为方案决策记录保留。

评审同意原方案中删除依赖可恢复基础、指纹缓存先测量、稳定页面来源、保护临时文件和区分任务重连／重新调用的原则。这些要求继续保留。

| 编号 | 意见 | 处理与判断 |
| --- | --- | --- |
| 1 | 先定桥接与传输，再决定是否需要令牌 | 采纳架构先定案；不采纳“有协议桥即可省略 TCP 后端认证”。首版确定 `app://` → 主进程桥 → 回环 HTTP，主进程注入令牌，页面不持有。桥不阻止其他本机进程直接连接；命名管道／Unix socket 也需权限与对端验证 |
| 2 | SQLite 评估应前置 | 采纳。SQLite 改为默认目标，在 D0 与 D1 间增加 S0，先验证选定运行时和故障用例；不先实现 JSON 跨记录事务框架。数据库事务／备份不自动覆盖原文件及 WAL 管理 |
| 3 | D0 缺资源门槛 | 采纳。加入安装包、安装占用、空闲内存、启动时间、文字 PDF／OCR 峰值和重复任务残留上限，明确基线与测量口径。这些是暂定验收门槛，不是实测数值 |
| 4 | Electron e2e 迁移工作未明确 | 采纳。D0 必须建立 Electron fixture，并让既有 38 个业务场景有桌面对应验证；保留 Node／HTTP 与 Chrome 基线。业务定位不一定全部重写，启动、故障注入和存储断言需适配 |
| 5 | `.env` 退出路径与在途配置未定义 | 采纳改造要求，修正求值时机：当前默认参数在调用时求值，并非模块加载时。新增统一设置提供器，桌面使用设置／系统凭据，开发模式显式使用 env；任务级配置快照、新任务热更新和撤销授权分别定义 |
| 6 | 无条件 `response.json()` 导致不可读错误 | 成立，前置到 D0。建立业务／连接／超时／取消／格式错误契约，覆盖 HTML、空响应和连接拒绝，保留下载及页图的二进制处理 |
| 7 | 降级恢复路径不完整 | 采纳。未知新格式停止读写，默认从兼容备份恢复到新目录，保留新版目录并提示升级后修改未包含；只读支持仅承诺已验证格式 |
| 8 | 首版多窗口边界不明确 | 采纳。首版确定单主窗口，第二次启动聚焦；多窗口对照后置并在帮助中说明。测试仍验证多个独立编辑会话及共享后端的并发保护 |
| 9 | 默认无正文日志不足以排查模型问题 | 采纳分级。默认不记录正文；用户可为单次任务开启详细诊断，说明内容范围，本地限额／过期清理，导出前预览，不自动上传；所有模式均排除凭据，原始页图单独选择 |

## 两个架构决定

1. **保留受保护的回环 HTTP。** 当前业务服务和 API 测试已经基于 HTTP，首版用受限协议桥复用这一路径。令牌只在壳层和后端，转发时注入请求头，闭合认证链路。若后续改为真正私有的父子进程 IPC，再重新评估令牌要求；不将两套传输同时列为首版工作。
2. **SQLite 优先，S0 验证后进入 D1。** 使用“删除被三个主题引用的文献并在不同步骤强制终止”的具体用例比较恢复机制；冻结驱动、事务、文件操作和备份方案后再写迁移。`node:sqlite` 是否无需另行编译依赖，取决于所选 Electron 后端构建是否实际包含该模块。

## 本轮核查结果

- 代码确认：`qa.mjs`、`comparison-model.mjs`、`report-model.mjs` 和 `vision.mjs` 的默认配置参数在函数调用时求值；视觉逐页调用更需要任务级配置快照。
- 代码确认：`app.js` 的 API 包装直接解析 JSON；已有浏览器测试通过 `page.route` 注入错误／迟到响应，部分用例读取网页存储。
- 本机探测：Node v24.12.0 可加载 SQLite 3.50.4，内存库事务回滚后记录数为 0，`integrity_check` 为 `ok`；同时输出实验性功能提示。未运行 Electron 打包探测，不能据此宣布 S0 完成。
- 本轮是文档调整，没有重跑未改动的业务测试。现有基线仍为上轮验证的 49 项 Node、38 条浏览器测试；新资源门槛及桌面自动化均待 D0 实现和测量。
