# D1 ZIP 资料库备份与恢复

日期：2026-10-23，补充更新 2026-10-25。本轮为 D1-03 增加 ZIP 容器和桌面入口；选择性恢复和损坏资料处理见 [D1 损坏资料说明](d1-record-recovery.md)。D1 整体仍在进行中，跨记录事务和兼容版本回退仍需继续。

## 桌面操作

在“资料库”菜单中选择“导出 ZIP 备份…”并指定新文件名。应用暂停后端，取得资料库锁，生成经过验证的目录快照，再逐文件压缩。生成的 ZIP 通过实际解压、CRC、SHA-256、版本及 SQLite 一致性检查后才发布；已有目标不会被覆盖。完成后重启原资料库。

选择“从 ZIP 备份恢复…”时先验证归档。通过后暂停后端，保存当前资料库的目录安全备份，将 ZIP 恢复到用户目录 `libraries/<uuid>` 下的新目录，检查并启动成功后才保存位置选择。安全备份、恢复、目标启动或位置写入失败时重启原库；来源 ZIP 和原库保留。恢复副本不包含备份时点之后的修改，后续修改仍保留在原库和切换前安全备份中。

目录备份和恢复入口继续可用。两种恢复均使用已有资料库草稿隔离机制，不把原库同 ID 的草稿应用到恢复副本。

## 离线工具

关闭使用资料库的应用后执行，目标父目录必须存在，目标文件或目录必须尚不存在：

```sh
node tools/storage-maintenance.mjs backup-zip /path/to/library /path/to/new-backup.zip
node tools/storage-maintenance.mjs verify-zip /path/to/new-backup.zip
node tools/storage-maintenance.mjs restore-zip /path/to/new-backup.zip /path/to/new-library
```

工具进度写到标准错误流，最终结果写到标准输出。`verify-zip` 不打开业务存储，不改变任务状态。工具和桌面维护进程调用同一实现。

## 容器与限制

- ZIP 根目录包含 `backup-manifest.json`，其余普通文件必须与清单逐项一致。保留 JSON 记录或 SQLite 一致快照、原文件、历史、文件操作日志和隔离内容；不包含根目录模型配置、`.env`、锁库或其他额外文件。
- 支持 STORE、DEFLATE 和 ZIP64 元数据，不支持加密 ZIP、符号链接或其他特殊文件。输出文件权限固定为 `0600`、目录为 `0700`，不继承归档中的可执行权限。
- 最多 200,000 个清单文件；ZIP 中含目录和清单在内最多 200,001 个条目。清单及 ZIP 目录元数据分别限制为 32 MiB，研究文件展开总量为 20 GiB；ZIP 文件本身最多 20 GiB + 256 MiB。单路径最多 4096 字符、64 层。
- 校验原始路径，不接受 `..`、绝对路径、反斜杠、盘符、数据流、重复条目、大小写或 Unicode 别名冲突、文件／目录冲突和清单之外的普通文件。检查声明大小，也在流式解压时检查实际字节数、CRC 和清单 SHA-256。
- 压缩和解压按文件流式执行，不把整库载入内存；快照和校验仍会占用额外磁盘空间。导出同时需要快照、ZIP 和校验展开空间；恢复前验证也会使用系统临时目录。操作失败时来源保留，错误信息给出备份或恢复暂存目录，不自动把失败副本当作资料库打开。
- ZIP 最终以同文件系统硬链接独占发布，避免覆盖在操作期间出现的同名文件；不支持硬链接的目标文件系统会拒绝发布并保留暂存副本，可改用受支持的本地目录或目录备份。
