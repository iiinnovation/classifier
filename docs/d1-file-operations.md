# D1-06：原文件操作日志首轮

日期：2026-10-21，补充更新 2026-10-25。状态：原文件日志、SQLite 导入跨记录提交和启动恢复已实现，删除产品语义与完整崩溃验收仍待完成。

原文件不与记录数据库共用事务，因此每次写入或删除先创建一个不含原文的操作记录：稳定 UUID、操作类型、文献 ID、相对路径、预期 SHA-256（删除可为空）、`pending` 状态和创建时间。文件操作成功后写 `done` 与完成时间；发生错误写 `failed` 和错误代码。JSON 资料库把日志放在 `.file-operations/`，SQLite 放在 `file_operations` 表；日志随 JSON 目录备份或 SQLite 一致快照保存。

服务启动时检查未完成操作。写入操作如果目标文件哈希与预期一致，直接标记完成；目标缺失或哈希不符记为失败并保留现场。删除操作如果目标已不存在视为完成，仍存在则重试删除；无法确认时记为失败。恢复过程记录 `recoveredAt`，不会把原文或密钥写入日志。资料库检查报告 pending／failed 操作，供用户保存清单后决定恢复或从备份处理。

Review 修复：已有 SQLite v1 库在通过版本和完整性检查后补建日志表，不改变记录格式或现有 generation。两种存储恢复前均校验日志 ID、文献 ID、操作类型、路径和写入哈希；只允许 `originals/<文献 ID>`，拒绝原文件或其目录为符号链接。JSON 日志通过临时文件写入、文件同步和重命名发布，在支持目录同步的平台继续同步目录；损坏、身份不符或指向符号链接的日志保留原字节、跳过恢复并列入检查清单，不阻断其他有效日志及记录的载入。未发布的 `.tmp` 文件不会被重放。

原有文件日志只记录和恢复文件动作，不决定用户是否应该删除文献、主题、笔记或历史；共享文献的删除语义属于 D2。2026-10-25 新增 SQLite 专用 `import_operations` 待办：暂存并发布原文件后，在同一事务中提交文献、主题关联、任务结果和 done 标记；提交前退出按身份及哈希清理未提交文件，提交后只清理暂存，不重放任务。详见 [原子导入说明](d1-atomic-import.md)。JSON 仍沿用原有逐记录路径；删除链路和所有故障边界尚未完成。

新增测试覆盖 JSON 日志脱敏、启动幂等恢复、失败操作清单、SQLite 日志及迁移后的新日志。此前 Electron 启动阻止记录保留为历史，后续打包验证见 [原子导入证据](measurements/d1-atomic-import-mac-x64-2026-10-25/validation.json)。

修复回归另覆盖旧版 SQLite v1 原始表结构、越界路径和文献 ID 不匹配、两种存储的文件／目录符号链接、损坏与符号链接 JSON 日志、写入哈希恢复，以及最终日志发布前的 EIO 和真实 SIGKILL 边界。完整断电及跨记录事务验收仍待完成。
