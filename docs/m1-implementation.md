# M1：研究主题与文献组织

状态：2026-10-08 已完成并验证。

本阶段落实 [产品框架](product-framework.md) 的 M1，覆盖主题创建与编辑、已有和新文献关联、人工书目信息、主题内筛选与阅读状态。M2–M4 按后续阶段实施。

## 最小数据模型

- `data/topics/<id>.json`：`id`、`title`（必填，200 字以内）、`question`（必填，4000 字以内）、`scope`（2000 字以内）、`createdAt`、`updatedAt`、`documents[]`。
- 每条主题文献关联：`documentId`、`addedAt`、`updatedAt`、`selection`（`pending` / `included` / `excluded`）、`readingStatus`（`unread` / `reading` / `read`）、`relevance`（相关性说明）、`reason`（筛选理由）。两段说明各最多 2000 字。
- 文献继续使用原 `id` 与原文件。书目信息编辑更新文献 `title` 和 `bibliography: { authors, year, venue, doi, url }`，均为字符串；旧文献缺少 `bibliography` 时按空字段显示。作者允许自由文本，年份为空或四位数字，来源链接仅允许 HTTP(S)。
- 书目信息跨主题共享；筛选、相关性、阅读状态存放在关联上，各主题独立。重复关联幂等，不重置状态。移除关联保留原文献、问答和证据。
- 原有解析 `schemaVersion`、原文件摘要、片段 ID、坐标和问答引用不变。编辑元数据不重新解析。日后跨文献引用以文献 ID 与片段 ID 共同标识，本阶段不增加跨文献问答。

主题关联嵌入主题记录，每次原子写入；同一记录的修改在进程内串行处理，避免同时关联或编辑造成覆盖。UUID 在入口统一为小写，使大小写不同的请求使用相同的关联身份与写入队列。继续沿用单进程 JSON 存储。

## HTTP 接口

| 接口 | 行为 |
| --- | --- |
| `GET /api/topics` | 主题列表与文献、纳入、已读数量 |
| `POST /api/topics` | 创建主题，返回 201 |
| `GET /api/topics/:id` | 主题详情，关联中包含文献摘要 |
| `PATCH /api/topics/:id` | 编辑标题、问题、范围 |
| `PUT /api/topics/:id/documents/:documentId` | 关联已有文献，幂等，返回 200 |
| `PATCH /api/topics/:id/documents/:documentId` | 更新该主题内的筛选、相关性、理由及阅读状态 |
| `DELETE /api/topics/:id/documents/:documentId` | 移除关联，保留文献，返回 200 |
| `PATCH /api/documents/:id` | 更新标题和书目信息；仅接受文档列出的可编辑字段 |

写入接口的非法字段或字段值返回 422，非法 ID 返回 400，不存在的主题、文献或待编辑关联返回 404。PATCH 接受部分字段。

`POST /api/imports` 和同步 `POST /api/documents` 的 multipart 表单增加可选 `topicId`。服务在解析前校验主题；后台任务记录目标主题，完成解析并保存文献后再关联，完成状态表示关联已保存。导入期间关闭窗口、切换主题或刷新页面不改变原任务的目标主题。若保存文献后关联失败，任务保留 `documentId` 供恢复；原文献仍能从全部文献中打开。

## 界面与恢复

主页列出研究主题，提供创建入口和全部文献入口。主题概览显示研究问题、范围、文献统计、筛选及阅读状态；支持导入、关联已有文献、编辑书目信息、记录筛选、移除关联和打开原有单篇研读工作台。

浏览器保存最近的主题和文献位置；刷新后恢复对应位置。主题、关联和全部编辑内容以服务端持久化为准。旧浏览器的最近文档记录仍可恢复；未归属主题的旧文献可从全部文献直接打开。

## 验收要求

1. 创建并编辑两个研究主题，重启后标题、研究问题、范围保持。
2. 同一份旧文献关联两个主题，分别编辑筛选理由、相关性与阅读状态；切换后互不混淆。
3. 编辑书目信息后两个主题均能看到；原文、引用和问答历史保持完整。
4. 在主题内导入新文献，刷新或切换主题后仍归属最初指定主题。
5. 移除主题中的文献关联后，另一主题与全部文献仍能访问原文献。
6. 并发关联和修改不丢记录；重复关联不重置已有状态；无效输入不会污染存储。
7. 浏览器完成创建、关联、编辑、导入、研读、切换与恢复流程，检查窄屏布局和错误提示。

## M1 代码审查与修复

本轮对正常流程之外的保存失败、响应乱序、恢复和并发边界补充回归，并修复以下问题：

| 问题 | 修复 |
| --- | --- |
| 保存成功后的列表刷新失败，使创建表单保留在可重复提交的状态 | 先采用已保存结果，再单独处理刷新错误；提示已保存并关闭表单，避免再次创建 |
| 保存中仍能编辑字段，后续输入未包含在已发出的请求中，却随表单关闭丢失 | 保存期间锁定表单字段，完成或失败后恢复可编辑状态 |
| 导入进度请求短暂失败，客户端清掉仍在执行的任务 ID | 网络错误、429 和服务端错误继续重试同一任务，保留恢复记录和取消入口 |
| 刷新后恢复导入时，将用户从已选主题带回导入目标主题 | 恢复只更新资料与进度，保留当前浏览位置 |
| 旧的文献列表响应覆盖新书目信息，重新编辑时可能再次保存旧值 | 统一文献缓存的请求版本，忽略过期响应；保存响应立即更新缓存 |
| 启动恢复或导入完成时，覆盖用户正在进行的页面切换 | 从开始打开文献时记录导航版本；已被新导航取代的恢复流程停止执行 |
| UUID 大小写不同导致重复关联，并在大小写不敏感文件系统上绕过同记录写入队列 | 统一 UUID 的存储路径、接口身份与导入目标标识 |
