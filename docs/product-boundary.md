# 产品与架构边界

## 产品主线与当前实现

产品定位于跨学科的文献研究工作台，以研究问题组织资料与成果：研究主题 → 收集与筛选文献 → 阅读与证据记录 → 比较与综合 → 编辑和保存成果 → 持续修订。定位、首版范围和阶段验收统一记录在 [产品框架与路线图](product-framework.md)。

当前已实现 M1 文献组织与 M2 阅读笔记。主题内可进入单篇研读链路：解析与引用定位 → 提问 → 阅读证据 → 带引用回答 → 保存和修订笔记 → 回到原文核验。多文献比较与研究总结属于 M3–M4，尚未实现。

当前文献库保存用户导入的论文、报告和研究笔记。本产品不以训练分类模型为目标，也不设置训练数据划分流程。

## 独立服务

API 服务负责解析、存储、检索、模型调用和任务状态；复杂文档使用独立 worker 后台解析，本地 OCR 不调用外部模型；Web 工作台通过 HTTP 调用 API。运行不依赖原桌面应用或 Tauri。原文件和引用定位是后续科研功能共用的数据基础。

M1 使用 `topics` JSON 记录保存主题及其文献关联，书目信息保存在原文献记录。对同一记录的编辑串行执行并原子写入，仍以单进程运行作为边界。关联关系和筛选状态按主题独立，原文件、解析结果与问答历史按文献共享。后台导入任务记录 `topicId`，在服务端完成文献关联。数据模型、兼容规则和验收见 [M1 实现说明](m1-implementation.md)。

M2 使用 `notes` JSON 保存笔记、证据快照和历史版本。引用同时包含文献身份、片段及解析内容指纹，书目信息不参与指纹；内容变化时显示保存的原文并要求重新核对。更新使用版本检查，模型建议复用问答任务但按主题归属保存，只有显式采用才创建笔记。未配置模型仍可使用手工笔记和原文证据。详见 [M2 实现说明](m2-implementation.md)。

## 当前单篇问答 Agent 循环

1. 服务确定性解析文件，并生成片段 ID；模型不参与文件解析。
2. 根据问题检索初始片段，将完整片段交给模型阅读。
3. 模型可以调用 `search_passages` 获取片段线索，再调用 `read_passages` 读取正文。
4. 仅接受引用本轮已读取片段的结构化回答；区分原文事实和归纳。
5. 限制模型请求轮次、工具调用总数、上下文长度和任务时间；重复工具调用复用结果。
6. 调用失败、回答结构错误或引用无效时，保留可查看的原文证据。

初始检索相当于自动阅读，允许直接引用。只搜索到但尚未读取的片段不允许引用。该约束解决引用身份与来源问题，后续主张核验功能仍需检查证据是否真正支持结论。

任务状态持久化；服务重启会将未完成任务标记为 `interrupted`，不会自动恢复上游模型请求。当前最多同时执行三个问答；超出容量返回 429。90 秒超时和主动取消都进入 `cancelled`，错误信息区分原因。

## 后续实现边界

沿现有文件、引用与问答基础，按以下依赖顺序实现首版文献研究任务：

1. **M1 已完成**：研究主题与文献关联、基本书目信息和筛选记录。
2. **M2 已完成**：可编辑的结构化阅读笔记、证据关联与人工纠正。
3. 主题内多文献比较、比较维度与条件说明。
4. 带引用的研究总结、编辑、版本保存与导出。

跨文献引用需要同时限定文献身份、片段及来源版本。实现时应确保已有文档仍可读取，人工编辑可以保存，重新解析或生成不会悄悄改变既有成果的证据来源。具体数据结构、迁移方案和 API 在各阶段实现前定义。

首版继续以本机单用户为运行范围。外部检索、URL 导入、DOI 自动补全、订阅追踪、专门学科模板、自动主张核验和团队协作属于后续评估内容。数据库、向量索引和额外任务调度设施依据具体需求选择。

复杂文档识别方式、结构字段与验证边界见 [复杂文档解析](document-parsing.md)。
