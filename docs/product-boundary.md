# 产品与架构边界

## 当前产品主线

论文或文档 → 解析与引用定位 → 提出研究问题 → 检索和阅读证据 → 带引用回答 → 回到原文核验。

文献库就是用户导入的论文、报告和研究笔记。当前产品不需要训练分类模型，也不设置训练数据划分流程。

## 独立服务

API 服务负责解析、存储、检索、模型调用和任务状态；复杂文档使用独立 worker 后台解析，本地 OCR 不调用外部模型；Web 工作台通过 HTTP 调用 API。运行不依赖原桌面应用或 Tauri。原文件和引用定位是后续科研功能共用的数据基础。

## Agent 循环

1. 服务确定性解析文件，并生成片段 ID；模型不参与文件解析。
2. 根据问题检索初始片段，将完整片段交给模型阅读。
3. 模型可以调用 `search_passages` 获取片段线索，再调用 `read_passages` 读取正文。
4. 仅接受引用本轮已读取片段的结构化回答；区分原文事实和归纳。
5. 限制模型请求轮次、工具调用总数、上下文长度和任务时间；重复工具调用复用结果。
6. 调用失败、回答结构错误或引用无效时，保留可查看的原文证据。

初始检索相当于自动阅读，允许直接引用。只搜索到但尚未读取的片段不允许引用。该约束解决引用身份与来源问题，后续主张核验功能仍需检查证据是否真正支持结论。

任务状态持久化；服务重启会将未完成任务标记为 `interrupted`，不会自动恢复上游模型请求。当前最多同时执行三个问答；超出容量返回 429。90 秒超时和主动取消都进入 `cancelled`，错误信息区分原因。

## 后续方向

在当前文档、引用、问答和任务接口上逐步增加：

- 多文献项目、标题和 DOI 等元数据。
- 研究问题、方法、样本、结果与局限的结构化提取。
- 跨论文方法对比、综述草稿、主张核验。
- 根据具体学科引入专用字段、工具和评价样例。

在实现某个垂直功能时，再决定是否引入数据库、向量索引或额外任务调度设施。

复杂文档识别方式、结构字段与验证边界见 [复杂文档解析](document-parsing.md)。
