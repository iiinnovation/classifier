# 本地桌面应用交付方案

日期：2026-10-09。修订：2026-10-19，按用户确认收敛当前平台范围。状态：D0 Mac x64 本机范围与 S0 已通过，D1 目录锁、显式 SQLite 适配及离线维护工具已实现，数据安全整体验收仍进行中；详见 [统一工作清单](work-items.md)。

本文件维护设计与验收约定；逐项实施状态以 [统一工作清单](work-items.md) 为准。进入桌面阶段前的代码和验收范围见 [M4 收尾基线](m4-closeout.md)。

M1–M4 完成的是研究工作流的首版功能和自动化验收，不代表桌面安装包已具备正式交付条件。本文承接用户转交的桌面交付清单，修正已完成项目、实现顺序及发布要求。M4 收尾功能基线为 49 项 Node 测试、38 条浏览器测试通过；后续 D0 实现与验证见工作清单，开发环境结果不等于安装包验收。

**当前交付和验收范围为 macOS 14+（x64），最低基线为 8 GiB 内存、SSD。** 2026-10-19 用户确认将 Windows 11 24H2+（x64）及 macOS 14+（arm64）后置，由工作清单 P-08／P-09 跟踪；它们不阻塞当前 Mac x64 的 D0 → S0 → D1 推进。恢复各平台交付前须补齐对应运行时、原生资源、数据恢复和安装包验收，不继承 Mac x64 的通过结论。平台范围缩减不放宽 Mac x64 的资源、最低系统／配置和干净机器验收要求。

## 1. 桌面壳建议

2026-10-19 补充执行决定：用户目前无其他测试电脑，允许本机 Mac x64 验证通过后继续 S0／D1。最低支持系统、8 GiB 最低配置和真实无开发环境机器验证保留为 D5-05 发布前门槛，不作为后续开发的前置条件。下文有关这些环境的要求继续有效，但执行时点后移；当前开发机上的测试不证明延期环境已兼容。

首版采用 **Electron** 作为执行选型，沿用现有 Web 界面及 Node 业务服务，API／解析任务在独立进程中运行，由桌面主进程管理其生命周期。具体 Electron 版本、进程启动方式与原生模块装载须通过 D0 验证后冻结；若达不到下文资源门槛，应在进入后续阶段前重新评估。

| 考量 | Electron | Tauri + Node sidecar |
| --- | --- | --- |
| 现有业务运行时 | 现有 Node API、worker 和文件操作可继续使用，仍需验证独立进程运行时 | 需要另行分发和管理 Node sidecar |
| PDF 与 OCR | 需打包原生 canvas、PDF.js 资源、Tesseract 和语言包 | 同样需要这些资源，并处理 sidecar 与壳层通信 |
| 页面一致性 | Chromium 渲染与现有 Chrome 测试较接近，仍需安装包测试 | 各平台 WebView 行为需另行验证 |
| 主要代价 | 安装包体积和基础内存较高 | 壳本身较轻，但总包大小仍受 Node、OCR、原生依赖影响，收益需测量 |

当前选择依据是降低首次交付的运行时与界面适配成本。没有实测安装包大小、内存或启动时间，不据此声称任一方案已经满足性能目标。

代码依据：项目使用 Node HTTP 服务、`worker_threads`、`child_process`，PDF.js 与 `@napi-rs/canvas`，OCR 调用 Tesseract 可执行文件。当前锁定的 PDF.js 6.3.289 声明 Node `>=22.13.0 || >=24`；桌面所选运行时必须满足并实际跑通这些依赖。

## 2. 运行与安全约定

**首版传输定案：固定 `app://classifier` 页面 → Electron 主进程协议桥 → 带实例令牌的回环 HTTP → 独立 Node 后端。** 保留现有 HTTP 业务入口及测试基础，渲染页面不直接访问本地 TCP 端口，也不持有令牌。

- 桌面数据使用操作系统的应用用户数据目录，不写安装目录或代码仓库。首次发现开发版 `data/` 时，经明确选择和备份后导入，不能启动即覆盖。
- 后端使用 `127.0.0.1` 和动态端口。桌面入口强制回环地址，不接受环境变量改为公开监听；启动成功后通过受控进程通信告知壳层实际端口，启动失败需要可见错误。
- 令牌由壳层与后端通过私有进程通信交换，只留在受信进程内存；主进程转发请求时注入专用请求头，后端先校验令牌再处理 API。后端重启更换令牌，旧令牌失效。令牌不进入 URL、日志、命令行、页面脚本或网页存储。
- 受限的协议桥只接受应用自身顶层页面的合法请求，转发允许的 API 路径与方法；禁止任意地址代理。后端同时校验自身 Host 和桌面来源策略。不得为兼容桌面而全局放行 `Origin: null` 或关闭 Origin 检查。
- 远程导航、任意窗口创建和系统打开行为受控。页面启用隔离与沙箱，不开放 Node 能力；需要的文件选择、导出和系统操作通过窄接口提供。
- 单实例包含两层：壳层第二次启动聚焦已有窗口；数据层对同一数据目录实行跨进程排他写入。数据锁必须早于扫描、迁移和重启任务标记，考虑异常退出、陈旧锁及 PID 复用，不只检查锁文件是否存在。

此处保留令牌的理由是 **后端仍有 TCP 监听**：协议桥限制了页面的调用路径，却不能阻止其他本机进程直接连接该端口。渲染页面无需“拿到令牌”，因此不存在向网页存储放密钥的必要。若后续改为只有父子进程持有的私有 IPC 通道，可以重新评估是否取消令牌；Unix domain socket／命名管道本身不自动隔离同用户进程，需要单独验证权限及对端身份。首版不同时实现两套传输。

本地 API 保护针对未经授权的页面／进程调用，不承诺抵御已控制应用主进程、调试权限或用户数据目录的攻击者。

**动态端口与草稿是相关问题。** 当前 `localStorage`／`sessionStorage` 按页面来源保存，端口变化会改变 HTTP 页面来源；`sessionStorage` 也不能作为关闭应用后仍可恢复的持久草稿。桌面必须同时解决稳定来源、持久草稿、编辑会话隔离和已有草稿迁移，不能只把 `listen(8790)` 换成 `listen(0)`。

**首版窗口范围：单主窗口。** 第二次启动聚焦原窗口，生产包不提供“新建工作窗口”，不开放任意弹窗；保留已有研读分栏，并在帮助中说明多窗口对照尚未支持。草稿需要持久化的编辑会话标识，不能依赖导航类型或 sessionStorage 判断应用重启后的归属。D0 固定稳定来源和可注入的草稿存储接口，验证第二次启动、来源在重开后保持一致及既有会话隔离；D3 完成跨应用退出／崩溃的持久恢复。测试环境仍可创建多个渲染页面覆盖既有并发场景。

## 3. 删除、损坏与迁移的先后关系

建议先建立可恢复的数据操作基础，再开放永久删除。现有 `store.update` 仅保证单记录队列和单文件替换；文献删除涉及多个主题、任务和原文件，跨文件操作仍可能部分成功。

**存储默认目标改为 SQLite，原文件继续放文件系统。** 在 D0 与 D1 之间增加 S0 存储决策关卡；通过前不编写 JSON 跨记录事务／重放框架，避免在评估之前形成实现依赖。现有 JSON 作为待迁移的旧格式和 D0 功能验证基础，尽量保持业务接口、证据快照和版本冲突语义。

S0 优先验证所选 Electron 后端运行时的 `node:sqlite`：模块实际可用、版本固定、事务与错误语义满足需求、打包后无需额外原生模块构建。不能把本机 Node 支持直接当成 Electron 打包后的保证；若不满足，应在 S0 明确替代驱动或存储方案及其成本。

SQLite 负责元数据、关联、任务和历史的跨记录事务。原文件的删除／替换仍与数据库事务分开，需记录待执行文件操作，处理提交后未删除文件、删除失败及重复恢复。SQLite 也不等于始终只有一个可复制文件：WAL 等辅助文件和活动连接必须按正确备份／关闭规则处理。数据库一致快照（如经过验证的备份接口或 `VACUUM INTO`）不自动覆盖 originals，整库备份仍需校验两者属于同一逻辑状态。

S0 的对比用例固定为：删除一篇被三个主题以及笔记、比较、成果引用的文献；在事务提交前后、原文件删除前后模拟进程被强制终止，并补测写入失败、第二进程竞争、重启恢复和备份还原。比较 SQLite 与 JSON 方案所需机制、失败状态、实现成本及可测试性，形成明确决策记录后进入 D1；不以“单文件”或少量成功路径代替验证。

顺序为：排他锁与数据目录确定 → 目录／记录版本识别及完整性检查 → 备份与恢复验证 → 坏记录隔离、迁移及批次恢复 → 删除预览与全链路删除。

### 删除语义先明确

| 操作 | 默认结果 | 必须保留或告知 |
| --- | --- | --- |
| 从主题移出文献 | 仅移除关联 | 原文件及其他主题继续可用，当前能力保持 |
| 从文献库删除文献 | 删除原文件与解析全文，处理主题关联及相关任务 | 已引用的摘录可继续保存在笔记、比较、成果及历史中；明确显示“原文已删除”，阻止原文定位和新任务读取 |
| 删除主题 | 删除主题及明确属于该主题的笔记、比较、成果等记录 | 共享文献库中的原文件不隐式删除；预览受影响记录和保留的共享资料 |
| 删除笔记／比较表／成果 | 删除目标记录及其自身历史，处理任务来源关系 | 被其他成果复制的快照继续可读；来源记录已删除需有明确状态 |

“删除原文件但保留引用摘录”不等于清除该文献的一切内容。若产品提供彻底清除，需要单独展示影响范围，处理其他记录及历史中的摘录，并告知备份和已导出的文件可能仍含副本。不能用同一个模糊的“永久删除”按钮承诺两种相反结果。

删除前检查活动导入和模型任务，防止任务完成后把记录重新写回。跨记录操作需可重试、可恢复，验证中途退出、磁盘写入失败及重复请求。永久删除由用户确认具体影响范围；归档继续作为可逆操作。

文档缺失容忍要覆盖详情、列表、历史、导出、来源选择、模型准备／采用与页面跳转，不能仅修改三个 `present()`。缺失、损坏和已删除应分别表达，不能把坏文件伪装成用户删除。

### 坏文件与迁移约定

- 列表不能因一条坏记录整体失败，也不能静默隐藏。保留损坏字节和原因，形成可见的隔离记录／恢复入口；直接读取该记录返回明确的损坏状态。
- 区分旧 JSON／业务记录损坏与 SQLite 数据库级损坏。数据库完整性检查失败时停止写入、保全数据库及有关辅助文件，进入备份恢复流程，不能通过“跳过坏行”假装已修复数据库。
- 临时文件可能是中断写入留下的唯一较新副本。持有数据锁后先检查主文件和临时文件，按规则恢复或隔离，再清理已确认无用的残留；不在启动时直接删除全部 `*.tmp`。
- 目录级 manifest 与各类记录格式版本分开管理。无版本号的当前资料作为显式旧版本处理；未来版本的数据目录应拒绝写入，并提供明确升级提示。
- 现有文档的 `schemaVersion` 属于解析结构，并参与证据指纹。新增业务记录／数据目录版本不能随意复用或改变其含义，避免纯存储迁移让旧引用全部失效。
- 迁移前验证备份完成，记录迁移批次与进度；支持中断恢复，完成后检查引用关系。保留旧数据、备份版本和兼容信息；不能把“有一个迁移函数”当作具备回滚能力。

### 降级恢复路径

旧应用发现不支持的新格式时，在任何任务状态更新或写入前停止打开该数据目录。默认提供“从兼容备份恢复到新目录”，使用升级前自动备份及其版本清单；完整保留当前新格式目录，不覆盖它。界面说明恢复到备份时间会缺少之后的修改，新版本仍可重新打开保留的目录。

仅对已明确声明并测试为可读的较新格式提供只读模式；未知格式不保证只读兼容，也不自动降级转换。没有兼容备份时提示使用支持该格式的应用版本。D1 必须验证：升级前备份 → 新版写入 → 旧版拒绝原地写入 → 从备份恢复新目录 → 新格式原目录保持完整。

## 5. 原清单遗漏的发布工作

1. **可独立安装的完整运行时。** 用户不应安装 Node、执行 `npm`、使用 Homebrew 或手改 `.env` 才能完成基本流程。按平台打包 OCR 可执行文件、语言包、canvas 原生模块、PDF.js 字体／CMap／WASM 等资源，并在无开发环境的机器验证。
2. **产品内设置和密钥管理。** 提供模型地址、模型名称、密钥、连接检查和撤销授权入口；使用系统凭据存储等明确的保管方案。更换服务地址或增加发送数据类型时重新告知。持续显示本地／外部处理状态；按下节明确 `.env` 退出路径与在途任务行为。
3. **安装与升级交付。** 当前先完成 Mac x64 安装包签名、macOS 公证等发布条件，验证安装启动、升级保留资料、失败回退和卸载的数据处理。Windows x64 与 Mac arm64 的相应验证在恢复平台交付时补齐。自动更新可后置，但手动升级路径必须可靠。
4. **真正的应用重启恢复。** 现有浏览器刷新和 API 重启测试不等于整个应用退出后草稿仍存在。需测试窗口关闭、API／渲染进程崩溃、强制退出以及旧版本数据打开。
5. **自动化及安装包验收。** D0 建立 Electron Playwright fixture 并保持既有 38 个业务场景在桌面传输下通过；后续阶段持续运行回归。用安装后的应用完成导入、扫描件 OCR、笔记、比较、成果、导出、删除、备份恢复和迁移；补充真实模型最小验证与至少不同类型的研究材料，明确质量限制。

### 运行时配置与在途任务

当前 `modelConfig(env = process.env)` 和各函数的 `config = modelConfig()` 默认参数是在函数调用时求值，**不是模块加载时**。现状的问题是配置来源为环境变量／注入的 `qaOptions.config`，缺少统一的可变设置入口、凭据管理及任务级快照策略。

- D0 先定义可注入的设置提供器接口，D1 确定非敏感配置的持久化位置与版本，D3 完成设置 UI 和系统凭据接入。问答、笔记建议、比较、成果、视觉解析、健康状态与连接测试统一经过该入口。
- 桌面发行版以用户设置和系统凭据存储为唯一配置来源，不自动加载安装目录／仓库的 `.env`，也不由环境变量悄悄覆盖已保存设置。开发命令保留显式的 `.env` 适配器；导入旧配置需要用户选择、查看服务地址并确认，密钥不进入普通数据备份。
- 用户保存设置后，新任务立即使用新配置，不要求重启。任务创建时解析一次不可变配置快照；任务的多轮请求和一个视觉导入任务的各页使用同一快照。密钥只在任务内存中使用，记录中只保存配置版本及允许公开的服务／模型标识。
- 普通配置修改不改变已启动任务的服务地址或密钥；界面说明旧任务继续使用原配置，并可主动取消。撤销模型数据授权则立即禁止后续发送并取消相关任务，不能以旧快照继续请求。任务重启恢复也不能自动重新调用供应商。
- 必须测试：任务 A 运行中更换配置，新任务 B 使用新配置，A 的后续轮次保持原配置；撤销授权停止 A／B；视觉任务不会跨页切换供应商；备份和日志均不含密钥。

### API 错误分层前置

统一客户端 API 适配层在 D0 就建立，D3 的重连体验使用同一错误契约。当前 `api()` 对所有响应直接 `response.json()`，需区分业务错误、连接不可达、超时、取消及协议／格式错误；保留 HTTP 状态和安全的诊断 ID，向用户显示可读消息。

根据响应状态和类型处理 JSON、合法空响应与非 JSON 错误。HTTP 200 的意外 HTML／空正文不能当成功，代理或桥接错误也不能退化为“Unexpected token”。下载和页图保持二进制通道，错误分层不能破坏它们。

自动重试只用于明确可重试的读取；保存／创建响应丢失显示“提交状态待确认”，利用操作 ID 查询结果，不盲目重发。D0 注入并自动验证：503 HTML、合法 204、意外空 200、损坏 JSON、连接拒绝、超时、取消、409，以及写请求已提交但响应丢失。

### 分级诊断

默认日志只记录事件、耗时、错误码和诊断 ID，并轮转；不记录原文、提示词或模型请求／响应正文。提供“为下一次任务开启详细诊断”，明确说明会保存实际发送内容及返回内容，以便复现引用问题。

详细诊断默认关闭，仅限用户选定的一次任务，任务结束或退出应用后关闭。原始页图需要另行明确选择。文件仅本地保存，使用当前用户权限；暂定保留最多 24 小时、上限 50 MiB，超限时标明截断。发送时采用的配置版本、片段身份和响应校验结果随记录保留；密钥、认证头及本地实例令牌始终排除。

诊断不自动上传；导出前展示内容和范围，允许取消或删除。数据用量和清除说明包含诊断副本，详细诊断文件默认不进入整库研究数据备份。D3 测试默认不留正文、明确同意后才留、一次任务后关闭、过期清理、导出预览和凭据脱敏。

### D0 资源门槛

以下为工程验收上限，**不是实测结果**。最低支持机器、系统和样本按当前 Mac x64 范围固定，仍以 macOS 14+、8 GiB 内存、SSD 为基线；Windows x64 与 Mac arm64 延期，不改变数值门槛和测量口径，恢复时逐平台／架构独立验收。若范围或门槛再次调整，应先明确记录，不在超标后静默放宽。

| 指标 | 暂定上限 | 测量口径 |
| --- | --- | --- |
| 安装包下载体积 | 每个平台、单架构 ≤ 350 MiB | 包含首发 OCR 程序和中英文语言包；不拿缺少必需资源的空壳包比较 |
| 安装占用 | ≤ 800 MiB | 不含用户资料、运行后缓存与诊断；这些另行统计 |
| 稳定空闲内存 | ≤ 450 MiB | 空资料库打开 60 秒后采样 30 秒，全部应用进程 RSS 总和的 P95；注明共享页可能重复计数，并附平台私有内存指标 |
| 进程冷启动可交互时间 | P95 ≤ 8 秒 | 20 次完整退出后启动，到页面可操作且后端就绪；不含安装、首次迁移，注明 OS 文件缓存条件 |
| 典型文字 PDF 导入峰值内存 | ≤ 1.2 GiB | 固定约 50 页、20 MiB 以内样本，一份任务，整个进程树峰值 |
| 典型 OCR 导入峰值内存 | ≤ 1.5 GiB | 固定 10 页、约 300 dpi 中英文扫描样本，包含 Tesseract 子进程 |
| 重复导入／取消后的内存残留 | 相对稳定基线增加 ≤ 100 MiB | 固定样本循环 10 次，结束后等待 60 秒、采样 30 秒，并检查子进程已退出 |

任一门槛超限均需在 D0 分析资源拆分、语言包选择、渲染生命周期或壳选型并重测；只记录“能启动”不能退出 D0。不能通过漏打包 OCR、降低既有证据处理正确性或省略测试来达标。

### 自动化迁移与持续回归

- 保留现有 Node／HTTP 测试以及 Chrome 回归作为业务基线；增加 Electron Playwright 启动 fixture，使用独立临时用户目录、受控模型和真实桌面桥接。D0 退出前，既有 38 个业务场景全部有桌面对应验证，不要求机械复制相同实现细节断言。
- 页面定位和业务操作尽量复用。`page.route` 的时序／故障模拟迁到测试专用的桥接或后端注入点；生产包不开放故障注入接口。浏览器存储直读改为用户可见恢复行为及测试存储适配器检查。
- 多标签页竞态场景不能因首版单窗口而直接删除：测试 fixture 可创建额外渲染页面验证独立编辑会话与共享后端；生产单窗口规则另有专门测试。
- 每次 IPC／协议桥、存储或草稿实现变化均运行对应桌面回归。D1 增加迁移、降级、磁盘失败和强制退出测试；D5 在实际打包应用与各目标平台运行安装／升级冒烟测试，不以开发模式 Electron 启动替代。

分页／索引、页图并发优化、前端请求票据收敛、进一步 fuzz 测试以及 URL／DOI／国际化等仍可按真实试用和风险反馈排期。对外发布前的基础恶意文件检查、安装包安全配置及 ZIP 恢复校验不因高级 fuzz 后置而省略。
