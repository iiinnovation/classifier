# D2 来源状态与已保存内容

本文记录缺失／损坏状态轮次。后续新增持久删除标记支持 `deleted`，并完成普通删除与来源展示联动；当前执行边界及独立证据见 [普通删除实施记录](d2-deletion-execution.md)。

日期：2026-10-27。对应 D2-03，目前仍为进行中。本轮统一来源缺失、记录损坏和暂时无法读取的展示，保留笔记、比较表、成果及其历史快照。实际删除、删除记录和“已删除”状态尚未实现，不能把找不到记录推断成用户已删除。

## 状态含义

| 状态 | 判定 | 展示与操作 |
| --- | --- | --- |
| `available` | 当前记录通过读取与结构校验 | 仍需核对保存的证据版本；存在记录不代表旧证据已与当前原文一致 |
| `missing` | 当前来源记录不存在 | 显示“原文缺失”或“来源材料缺失”，保留保存时的摘录与正文 |
| `corrupt` | 当前记录解码、结构或安全校验失败 | 显示“记录损坏”；沿用已有原件保全与隔离机制 |
| `unavailable` | 当前记录因读取失败暂不可用 | 显示“暂时无法读取”，不混同于缺失或损坏；读取恢复后重新计算状态 |

这些是记录的读取状态，不是对原始附件文件是否完整的额外扫描。原始附件缺失仍由资料库检查与实际文件读取报告。一个来源可用时，其证据也必须有明确版本且匹配当前文献 ID／版本，才允许跳转和核对；缺失版本不能因为两边均为空而被视为匹配。

状态在请求时由当前来源计算，不写回已保存证据、不增加研究记录版本。历史版本也展示其来源现在是否可用，同时保留原来的摘录、内容和版本号。损坏记录读取仍可能触发既有隔离保全，这不等于改写研究快照。单次展示缓存同一来源的读取，下一次请求重新核对；不承诺外部文件并发变化下的事务一致快照。

## 已覆盖流程

- 主题文献和笔记列表区分三类异常；原文不可用时，可从“查看笔记与历史”阅读已存内容。归档笔记也有可展开入口。从历史恢复为新版本后立即刷新主题笔记列表。
- 笔记内容编辑、归档和历史恢复不再依赖原文仍可读取；替换证据、确认已核对和新模型建议仍要求有效原文。页面禁用无法定位的原文入口。
- 比较表当前内容和历史分别检查各自的文献证据与复制笔记来源。来源笔记丢失或损坏时保留单元格内容并提示；比较生成与采用在服务端重新检查来源，拒绝继续发送或采用失去依据的建议。
- 成果列表、正文、材料、历史、引用和 Markdown 导出显示来源状态。取消选择某项材料后，已加入正文的段落仍通过 `origin.sourceKey` 保留来源关系和异常提示。
- 新材料选择禁用不可用的原文和研究材料；已有材料快照可以保留或移除。生成与采用使用当前来源检查；已完成但来源随后失效的模型草稿仍可阅读，出处显示具体状态，不能跳转到失效原文。
- 原文恢复可读且版本一致后，状态自动恢复，无需重写成果或给历史证据伪造新版本。

客户端限制用于明确反馈，服务端独立校验。测试使用受控模型回复，不发送真实研究内容，也不构成模型供应商质量验收。
