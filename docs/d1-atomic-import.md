# D1 SQLite 导入的跨记录提交

日期：2026-10-25。本轮把同步和后台 SQLite 文档导入的文献记录、主题关联及任务结果放进同一事务，并补齐原文件在提交前后的恢复。旧 JSON 库保留原有导入路径；尚未开放删除入口，也未引入 JSON 跨记录事务框架。

## 提交顺序

1. 解析完成并核对原文件 SHA-256 后，持久写入 `import_operations` 待办。记录只含操作 ID、文献／任务 ID、相对路径、预期哈希、状态与时间，不存原文或模型凭据。
2. 把原文件写到 `originals/.import-<操作ID>.tmp`，同步文件内容后，以独占硬链接发布到新文献 ID。已有目标不覆盖。支持的平台继续同步目录项。
3. 再次检查取消状态，进入最终提交区间。在 SQLite `BEGIN IMMEDIATE` 事务内读取最新主题及任务，核验任务仍为 queued/running，然后一起提交文献、主题关联、任务 completed 结果和导入待办 done 标记。事务中不跨 `await`。
4. 提交成功后清理暂存文件。暂存清理失败不把已完成任务改成失败；启动时会重新核对。

后台解析的进度写入在最终提交前排空，避免较早的 running 快照覆盖已完成任务。主题关联基于事务内的最新记录，不用解析开始时的旧快照覆盖其他导入或人工编辑。取消与关闭在最终提交前生效；进入提交区间后等待提交及清理结束，再释放资料库所有权。

## 中断与错误

导入待办状态是 pending、done 或 aborted。重启时先核对导入文件，再更新其他未完成任务：

- **未提交**：pending 且没有文献记录时，先核对原文件与暂存文件的哈希，以及原文件确为该暂存文件的硬链接；通过后才清理，随后标记 aborted。文献、主题关联及任务完成结果均未提交；任务按原有规则成为 interrupted。
- **已提交**：文献、关联、任务结果与 done 标记已经一起持久化。启动只清理匹配的暂存文件，不重新写主题或重放任务，不重新解析或调用模型。
- **无法确认**：路径／身份不合法、符号链接、文件哈希或硬链接身份不符、pending 与已有文献记录冲突时保留文件，在离线检查清单中报告，不猜测删除。
- **事务失败**：SQL 约束失败会回滚所有关联记录；原文件按上述待办规则清理。文件发布失败、提交前取消也不会提交文献或主题关联。

SQLite 初始化及已有 v1 库会补建独立的导入待办表；原 records 格式、generation 和既有文件操作日志不变。普通 SQLite 备份通过一致数据库快照包含该表，恢复后沿用相同的本地核对流程。文件复制可能丢失硬链接关系；若备份中仍有未提交文件，恢复后无法确认链接身份时会保留并报告，不能保证自动清掉这些残留。独占发布依赖目标文件系统支持硬链接，不支持时会在元数据提交前失败。

## 验证与边界

Node 新增 17 项专项测试，覆盖同步／后台 HTTP 导入、并发主题修改保留、已有文件冲突、任务状态冲突、取消、发布 EIO、SQL 约束回滚、提交确认边界错误、路径伪造及哈希不符。五处真实 SIGKILL 位于待办写入、暂存同步、原文件发布、事务提交前和提交后；逐项核对重启、重复重启和备份恢复。

最终源码与打包运行证据见 [本轮验证记录](measurements/d1-atomic-import-mac-x64-2026-10-25/validation.json)。打包存储专项另在真实 utility 进程中验证暂存同步、提交前、提交后三处 SIGKILL，并检查实际到达的故障点。进程强杀不等于真实断电或物理磁盘耗尽。

本轮收尾的是 SQLite **导入**的跨记录提交。共享文献删除、主题删除、历史与引用清理仍需 D2 明确语义后实现；原有 JSON 导入也不能据此声明拥有跨记录原子性。真实磁盘故障、最低配置、干净机器和其他平台验收继续保留。
