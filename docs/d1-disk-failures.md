# D1 磁盘错误与恢复边界

日期：2026-10-26。对应 D1-02／03／04／06。本轮补齐生产存储路径的磁盘错误专项，D1 整体仍按 [工作清单](work-items.md) 跟踪。

## 修复的行为

1. **保留 SQLite 的真实磁盘错误。** SQLite 在 `SQLITE_FULL` 后可能已经自动回滚。记录更新、迁移批次和选择性恢复在回滚报错时仍保留原始写入错误，避免把“数据库或磁盘已满”覆盖成“没有活动事务”，也不依赖较新 Node 才提供的事务状态属性。失败后原记录、历史、迁移进度及关联不发生部分提交；恢复写入条件后可以重试。
2. **报告实际副本位置。** 目录改名或 ZIP 硬链接发布成功后，父目录同步仍可能失败。此时操作继续报错，不承诺持久化完成；错误说明已出现副本的真实路径、同步失败和需要核验的状态。目录恢复、保全和选择性恢复不再只指向已经移走的暂存路径；已有目标仍不覆盖。
3. **迁移续跑重新确认同步。** 目录已发布但父目录同步失败时，续跑重新同步父目录。`ready` 标记已经可见但同步未完成时，再次续跑同步版本清单、迁移目录和父目录后才返回完成，不重放记录或覆盖完成后的用户编辑。

没有新增资料格式、后台自动迁移或永久删除入口。SQLite 的 `formatVersion`／`user_version` 仍为 1。

同一套测试只在隔离临时目录执行，测试 helper 可以分别加载工作区源码和指定 Mac x64 包内的生产模块。应用入口不开放故障开关。

| --- | ---: | --- |

| 迁移文件／发布 | 6 | 部分复制后 ENOSPC、文件同步 EIO、原文件发布 EACCES、目录发布后同步 EIO、ready 清单短写、ready 可见后的同步失败；验证进度及同批次重复续跑 |

SQLite 满载通过限制真实连接的 `PRAGMA max_page_count` 触发，不伪造 SQL 错误。文件系统的 ENOSPC／EIO／EACCES 在实际生产 I/O 调用处注入；短写场景会先写入部分字节再返回错误。未提交导入的部分暂存文件无法匹配预期哈希时会保留并报告，不猜测删除。提交已成功但清理失败不把任务改成失败，重启后再次核对清理。

## 验收边界

上述测试验证错误处理与恢复状态，**不等于物理磁盘占满、硬件断电或文件系统故障实测**。同日后续已对相同包补充 [9 个有界 APFS 真实空间耗尽场景和 6 个回退格式样本](d1-full-volume.md)，其证据单独归档，不改变本轮注入测试的性质。它们也不替代最低配置／干净机器、完整资源测量、真实研究资料或模型供应商质量验收。历史早期 D0 包没有新版格式防护，仍不得直接打开 SQLite 资料库。删除链路及其跨记录协调继续由 D2 跟踪；实际发行版本对与剩余验收条目仍需核对，不能仅凭专项通过宣布 D1 全部完成。
