# D2 普通删除与已删除来源

日期：2026-10-27。对应 D2-01／02／03。用户已同意首版普通删除保留其他研究中的引用摘录、删除主题保留共享文献，并将彻底清除所有副本后置。本轮实现实际执行、任务协调、文件待办恢复和可核验的“已删除”状态。

2026-10-28 补齐本轮验收归档和状态收尾。以下结果来自上一轮已执行并通过的完整验证；本次核对日志、运行时记录、截图、源码及产物哈希，不重复声明为新跑测试或重新打包。

## 产品语义

| 操作 | 删除范围 | 保留范围 |
| --- | --- | --- |
| 删除文献 | 文献记录及解析全文、原文件、全部主题关联及直接所属任务记录 | 笔记、比较、成果中的已保存摘录、复制内容和历史 |
| 删除主题 | 主题及属于它的笔记、比较、成果、自身历史及直接所属任务记录 | 共享文献库中的原件、其他主题和其他研究中的复制快照 |
| 删除笔记／比较／成果 | 目标及自身历史、直接所属任务记录 | 原始文献、其他记录中的复制内容及历史 |
| 移出主题 | 沿用现有关联移除操作 | 原件、研究记录与历史 |

删除影响仍由 GET 读取，不产生研究记录写入。SQLite 库的弹窗显示受影响记录、历史、所属任务和保留内容；必须勾选确认后才能点击“确认普通删除”。有活动任务时，确认文字包含停止任务的数量。刷新会取消先前勾选，迟到响应不会替换另一个目标。

旧 JSON 库继续提供预览，执行返回 422，并提示通过“资料库”菜单显式备份、迁移到 SQLite；不会自动转换资料库，也不以逐文件删除模拟跨记录事务。目标损坏、未知记录类型、范围变化或未完成的文件清理会阻止删除，要求先检查资料库。普通删除不清理备份、隔离副本、导出文件和其他未受管副本。

## 提交与恢复边界

生产入口 `DELETE /api/{documents|topics|notes|comparisons|reports}/:id` 要求：

```json
{
  "operationId": "客户端为本次确认生成的 UUID",
  "revision": "当前影响范围的 SHA-256",
  "policy": "retain-copied-evidence-v1",
  "confirmed": true,
  "stopTasks": true
}
```

`revision` 是确认范围校验值，不是直接删除许可。任务事件、进度和状态更新不让同一确认范围失效；研究内容、任务身份、导入最终关联等变化仍需刷新。服务先阻止新写入并排空已接纳的 HTTP 写请求，再停止并等待相关模型／导入任务。无关任务保持原有执行；相关任务已停止但删除提交失败时，不自动重新调用模型。

SQLite 同步事务重新校验当前记录和范围、相关任务已经结束、未知记录类型不存在，然后一起提交：

- 删除操作回执与各记录的删除标记。
- 文献／主题／研究记录、自身历史和所属任务记录的删除。
- 所有相关主题关联更新。
- 原文件删除待办及预期 SHA-256。
- 第一次实际删除时的 `PRAGMA user_version=2`。

事务内没有跨 `await` 持锁。记录 ID 的删除标记会拒绝旧任务或旧创建请求重新写回，更新队列同时保留现有版本冲突检查。重复使用同一 `operationId` 和确认范围返回已保存回执；把同一 ID 用于其他目标或范围返回 409。提交后的确认异常以持久回执判断，避免把已经提交的删除当作未执行。

原文件只在提交后清理，核对路径、普通文件类型、文件身份和哈希，拒绝符号链接和不匹配的替换文件；unlink 后同步目录，再确认完成。缺失文件按匹配的待办幂等处理。文件或日志确认失败时，研究删除已提交，响应显示 `filePending`，资料库健康检查列出待办；重启或重复原请求会重试。不会把文件清理失败描述为完整成功，也不会撤销已提交的记录删除。

首次删除前库仍为 SQLite v1，打开只补建兼容日志表。实际删除才在同一事务中升级为 v2，旧 D1 程序会拒绝写入。用户若需要回退，应先保存删除前的兼容备份，并恢复到新目录；不会在旧程序中原地继续编辑 v2 库。

## 来源与数据保留

来源现在区分 `available`、`missing`、`corrupt`、`unavailable` 和 `deleted`。只有匹配的持久删除标记才能得出“已删除”，找不到记录仍为“缺失”。标记或回执损坏时停止打开 v2 库，不通过忽略标记允许记录复活。

笔记、比较、成果、材料快照、历史和 Markdown 导出保留已保存内容，同时显示已删除来源；原文跳转、新来源选择、生成和采用在页面及服务端分别核验。其他主题中复制的研究内容继续可读、可导出。状态展示不重写证据或增加成果版本。原子导入的暂存清理认识已删除文献，既不恢复原件，也不把正常删除误报为未提交导入。

整库备份／恢复、检查与选择性恢复可读取受支持的 v2 数据库；恢复删除后的快照保留删除标记，恢复删除前的完整快照是用户明确选择的历史回退。用量仍按实际文件长度与内容估算分别统计，SQLite 文件不会因删除记录而自动缩小。
