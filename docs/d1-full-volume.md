# D1 有界满盘与回退基线

日期：2026-10-26。补充 D1-02／03／04／05／06 的验证，使用与 [37 个磁盘故障专项](d1-disk-failures.md)相同的 Mac x64 预览包。本轮没有改动应用代码或重建安装包。

## 真实文件系统空间耗尽

新增测试创建并挂载 **128 MiB APFS 磁盘镜像**，确认挂载设备与宿主卷不同、容量不超过 256 MiB 后，只向镜像写入填充文件。宿主至少保留 512 MiB 可用空间才能开始；测试结束先卸载镜像，再移除临时目录。此次挂载容量为 134,176,768 字节，已确认镜像卸载及临时目录清理。

测试通过真实打包应用的 utility 进程加载 ASAR 内生产模块，未替换文件系统调用，也未设置 SQLite 页数上限。先用大块写入，再用 64 KiB／4 KiB 小文件耗尽可分配空间；各场景均实际收到 `ENOSPC`。APFS 此时仍报告约 3.05 MiB 空闲，不能用 `statfs` 非零推断后续写入一定成功。备份／恢复释放 1 MiB 预留文件后继续操作，原文为 4 MiB 随机数据，仍触发真实分配失败。

**1 个打包测试、9 个场景全部通过：**

| 场景 | 实际失败与恢复结果 |
| --- | --- |
| JSON 编辑 | `ENOSPC`；已保存记录／历史不变，释放空间后重试成功 |
| SQLite 编辑 | `SQLITE_FULL`（13）；原记录不变，释放空间后重试成功 |
| SQLite 导入 | 原文件暂存创建失败；文献与主题关联未部分提交，重启后任务为中断，重新导入成功 |
| 目录备份／恢复 | 原文复制失败；目标未发布、来源仍可读，释放空间后完整校验通过 |
| ZIP 备份 | 快照复制阶段失败；来源保留、目标未发布，释放空间后生成并校验 ZIP |
| ZIP 恢复 | 写入失败；ZIP 与来源保留、目标未发布，释放空间后恢复并逐项核对 |
| 迁移续跑 | 3 条记录已提交后原文复制失败；释放空间后进度仍为 3 条记录／0 个文件，连续两次续跑成功 |
| 损坏隔离 | 保全失败可见、健康资料可读、坏字节原样保留；释放空间后重试隔离成功 |

迁移在满盘时查询进度还出现 SQLite 扩展 I/O 错误 `4874`，因为读取 WAL 资料库也可能需要共享内存空间。测试记录该错误，没有把它当作“进度为零”或成功；释放填充空间后重新读取并核对持久进度，再完成迁移。实际操作遇到这种情况，应先在目标卷释放空间，再检查原迁移目录并续跑，保留来源和固定备份。

本轮 ZIP 备份失败点在快照复制阶段，不据此声称已实际占满 ZIP 流写入阶段；该边界的短写／同步／发布错误继续由前轮注入测试覆盖。

- ASAR SHA-256：`1bfbd9fe709592544bd660f2a4809677b8bd7e34e414432bb8d8d58a137f51c8`。
- 标识：`mac-x64-d1-2026-10-26-d7a392b67465`。多个预览包都叫 `0.1.0`，必须同时核对日期和哈希。
- 格式：JSON／SQLite，目录／ZIP 备份；当前资料格式、记录版本和 SQLite `user_version` 均为 1。

新增 **1 个打包测试、6 个兼容恢复场景**：JSON／SQLite × 目录／ZIP 的未来资料格式，加上 SQLite 未来记录版本和未来数据库版本。每个场景先创建兼容备份，再写入后续修改和运行中任务、设置未知版本并加入未知目录；确认当前包启动时先拒写，任务不被改写。随后通过生产恢复入口恢复到新目录，核对备份时点的正文、历史和原文，保留较新资料库及未知内容，保全副本哈希匹配，恢复库重启后仍可编辑。

这些较新版本是**测试构造的格式样本**，不是另一个真实发行二进制写出的资料库。因此此登记仅为后续升级测试保留预览恢复基线，`releaseApproved` 和 `actualCrossVersionPairsVerified` 均为 `false`。历史早期 D0 包缺少当前防护，不列为安全回退包；只有历史哈希而本地包已不保留的构建也不据此获得回退支持。

## 复跑与回退操作

在项目根目录执行：

```sh
node tools/verify-rollback-baseline.mjs
CLASSIFIER_PACKAGED_EXECUTABLE="$PWD/dist/desktop-d1-disk-failures-2026-10-26/mac/Classifier.app/Contents/MacOS/Classifier" node node_modules/@playwright/test/cli.js test --config=playwright.volume.config.mjs --reporter=line
CLASSIFIER_PACKAGED_EXECUTABLE="$PWD/dist/desktop-d1-disk-failures-2026-10-26/mac/Classifier.app/Contents/MacOS/Classifier" node node_modules/@playwright/test/cli.js test --config=playwright.rollback.config.mjs --reporter=line
```

满盘测试仅支持 macOS，需要允许 `hdiutil` 创建／挂载临时镜像以及启动桌面应用。它不接收任意宿主卷作为填充目标。若卸载失败，测试报错并保留临时目录，不递归删除挂载卷。

校验工具检查本地 ZIP、ASAR 和已归档兼容恢复结果是否匹配登记，缺包或不匹配即失败；这是产物一致性检查，不替代签名、公证或可信分发。准备后续升级时须同时保留该包、回退登记、验证记录以及升级前完整兼容备份。实际回退仍由用户在启动恢复入口选择备份、保全和新目录，确认回退时点后执行；不得用早期 D0 包直接打开新库，不覆盖较新资料库。具体操作见 [兼容恢复说明](d1-compatibility-recovery.md)。

## 证据和剩余验收

原始报告、日志、清理结果、75 个应用／测试／工具／登记与依赖文件的哈希及相同 ZIP／ASAR 哈希见 [补充验证](measurements/d1-full-volume-mac-x64-2026-10-26/validation.json)。应用 63 个文件与前轮已验证源码一致。Electron 44.7.0、包内 Node 24.21.0、SQLite 3.53.4。前轮 Node 300/300、存储 15/15、桌面 18/18 仍属于 [原轮次证据](measurements/d1-disk-failures-mac-x64-2026-10-26/validation.json)，本轮未重跑这些整套回归。

这次验证覆盖真实 APFS 分配失败和释放空间后的恢复，没有占满宿主卷，也不代表物理 SSD 故障或硬件断电验证。既有 SIGKILL／同步错误专项保留其各自边界；硬件断电不自动扩展为要求切断开发机电源的操作。D1 仍需按验收清单核对，真实发行版本对的升级／降级流程在对应构建存在后执行，并纳入 D5-01。当前包未签名／公证，最低配置、干净机器、资源和真实供应商质量验收继续单独跟踪。
