本文件是后续实施状态的统一入口。产品目标见 [产品框架](product-framework.md)，架构与验收门槛见 [桌面交付方案](desktop-release-plan.md)，已完成工作见 [M4 收尾基线](m4-closeout.md)。评审记录保留原始判断与当时处理结果，后续任务状态在这里更新。

## D0：桌面运行验证

Electron、`app://classifier` 协议桥、由主进程注入实例令牌的回环 HTTP、独立 Node 后端、单主窗口已作为执行方案。平台暂按 macOS + Windows，最低系统版本和具体 CPU 架构在 D0-01 固定。

| 编号 | 工作 | 状态 | 完成证据／约束 |
| --- | --- | --- | --- |
| D0-01 | 固定首发平台、架构、最低支持机器和 Electron／Node 版本 | 待开始 | 记录目标矩阵与测试机器；满足 PDF.js／原生依赖的运行时要求 |
| D0-02 | Electron 单主窗口与独立后端生命周期 | 待开始 | 能启动、关闭、显示启动失败；第二次启动聚焦已有窗口，无遗留子进程 |
| D0-03 | 稳定应用来源、回环动态端口与实例认证 | 待开始 | 页面不持有令牌；未授权直连被拒绝；后端重启令牌轮换；禁止任意代理和远程窗口 |
| D0-04 | 打包 canvas、PDF.js 资源、Tesseract 和中英文语言包 | 待开始 | 无 Node／Homebrew 的目标机器完成 PDF 导入、页图和 OCR；列出全部分发资源 |
| D0-05 | 统一 API 错误分类与可注入设置提供器接口 | 待开始 | 覆盖非 JSON／空响应、断连、超时、取消、409、提交结果未知；下载保持二进制；配置来源可替换 |
| D0-06 | 草稿存储接口、稳定来源和编辑会话标识 | 待开始 | 来源在重开后一致，已有会话隔离成立；完整跨退出恢复在 D3-03 验收 |
| D0-07 | Electron Playwright fixture 与现有业务场景迁移 | 待开始 | 38 个既有场景均有桌面对应验证；保留 Node／HTTP 和 Chrome 基线；故障注入仅在测试环境开放 |

SQLite 是默认目标，原文件继续保存在文件系统。S0 通过前不先编写 JSON 跨记录事务框架。

| 编号 | 工作 | 状态 | 完成证据／约束 |
| --- | --- | --- | --- |
| S0-01 | 验证打包后端的 `node:sqlite`／明确驱动选择 | 待开始 | 固定运行时、驱动与版本；本机内存库探测已做，但不能替代 Electron 打包验证 |
| S0-02 | 用共享文献删除场景比较事务与文件恢复方案 | 待开始 | 三个主题引用同一文献，在提交／文件删除前后强制终止、磁盘失败、重复请求及第二进程竞争后均能恢复 |
| S0-03 | 冻结存储、迁移与一致备份设计 | 待开始 | 明确数据库事务和原文件操作边界、WAL 处理、旧 JSON 导入、备份还原和验收用例，再进入 D1 |

## 下一步与维护规则

M4 收尾提交完成后，**从 D0-01 开始，随后落实 D0-02／03 的最小运行链路**。D0 的原生资源、自动化和资源测量必须全部验收后才进入 S0；S0 决策通过后进入 D1。暂不实施全链路删除、用户数据迁移或性能架构改写。
