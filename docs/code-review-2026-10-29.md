## 已修复的问题

### R1：超限记录会在保存成功后变成不可读（P1）

读取端按 32 MiB 拒绝超限记录，JSON 与 SQLite 写入端原先没有对应的提交前检查。笔记／比较／成果的完整历史不断追加时，可以先保存成功，再在刷新后被识别为超限损坏记录。

已添加共享 UTF-8 序列化大小检查，JSON 临时文件发布和 SQLite INSERT／UPDATE 之前均会拒绝超限记录，返回 413。更新失败保留旧版本，SQLite 事务回滚，新记录不落地。生成任务结果或事件超限时，会保留可容纳终态的已保存查阅记录、写入明确的失败／取消状态，避免任务表面上一直运行。

JSON／SQLite 回归分别覆盖直接写入、更新、新建、重开、健康状态，以及超限任务结果／事件的可读终态。测试使用多字节中文，检查实际 UTF-8 字节数。

### R2：可读旧文献缺少可选提醒字段时，阅读页会报错（P2）

记录兼容规则允许旧文献省略 `warnings`，但阅读页直接调用其 `join`／`filter`／`length`。已在读取后的内存展示对象中补上空数组；不修改保存的原文、记录或证据版本。

现有阅读／切换测试使用省略该字段的文献，验证提醒区正常隐藏，并继续验证提问状态与迟到响应保护。
