# S0 存储决策（2026-10-19）

结论：Mac x64 当前打包运行时采用内置 node:sqlite；元数据、关联、任务和历史进入 SQLite，原文件继续保存在文件系统。S0 验证通过，可以进入 D1。这里冻结的是设计与驱动选择，尚未将现有用户资料迁移到 SQLite。

## 运行时与实验边界

在 2026-10-19 的真实 Mac x64 打包应用中，通过与后端相同的 utilityProcess.fork 机制启动隔离探针。实际运行时为 Electron 44.7.0、Node 24.21.0、SQLite 3.53.4。使用内置驱动，无额外原生数据库模块构建。测试 helper 位于包外，不向正式后端加入故障注入接口；决策时产品后端仍使用 JSON。此后 D1 已加入显式迁移和双格式识别，现有 JSON 不自动转换，当前实现见 [D1 实施记录](d1-implementation.md)。

证据见 [storage-validation.json](measurements/s0-mac-x64-2026-10-19/storage-validation.json)。该记录绑定 D0 包 ASAR 和 ZIP 哈希。相同场景也在开发 Node 子进程中执行。其他平台、最低系统与最低配置仍需后续独立验证。

## 验证结果

固定资料包含一篇被三个主题引用的文献，笔记、比较、成果及其历史中的证据快照，以及关联任务；另保留不应受影响的共享原文件。执行以下八类场景：

| 场景 | 验证结果 |
| --- | --- |
| 事务提交前 SIGKILL | 全部记录回滚，原文件与引用保留，重试正常完成 |
| 事务提交后 SIGKILL | 删除元数据与文件待办一并提交；重启执行文件待办 |
| 原文件 unlink 前 SIGKILL | 文件仍在、待办 pending；重启完成删除 |
| unlink 后、待办确认前 SIGKILL | 缺失文件按幂等成功处理，重启将待办标为 done |
| 数据库写入空间不足 | 用 max_page_count 触发真实 SQLITE_FULL；跨记录写入完整回滚 |
| 文件删除失败 | 在 unlink 边界注入 EACCES；保留 pending 和错误，恢复后重试成功 |
| 第二进程竞争 | 持有写事务时第二进程被拒绝；持锁进程强制退出后可重新取得锁 |
| 一致备份恢复 | 停写期间 VACUUM INTO + 原文件哈希清单；源库后续删除不影响恢复到新目录的副本 |

每个崩溃场景核对 integrity_check、三个主题、任务、快照与历史，以及不相关原文件；恢复和删除重复执行不增加操作、不损坏快照。测试模拟进程终止，不据此宣称硬件断电场景已验证。活动模型／导入任务的生产协调仍属于 D1／D2。

## SQLite 与 JSON 的比较

| 问题 | 当前 JSON 存储 | SQLite 决策 |
| --- | --- | --- |
| 三个主题、文献、任务一起更新 | 当前仅单记录队列与单文件 rename；跨记录需要另建日志、重放及幂等框架 | BEGIN IMMEDIATE 中原子提交，异常回滚 |
| 两个进程竞争 | 现有内存更新队列不能保护跨进程 | 数据目录持有专用 SQLite 锁连接；业务库仍使用短事务 |
| 原文件删除 | JSON 也需要记录待办并恢复 | 同一事务写 file_operations；提交后执行并持久确认 |
| 一致备份 | 必须停写整个资料库并校验文件集合 | 同样需要应用级停写屏障，SQLite 快照只覆盖数据库 |
| 实现与维护成本 | 需要维护自定义跨记录提交协议 | 使用已验证数据库事务，将自定义机制限制在文件操作边界 |

JSON 侧依据现有 store.mjs 的机制分析，不声称已经实现或测试了另一套 JSON 事务框架。

## D1 实施约定

1. **排他所有权先于扫描。** 数据目录使用专用 .classifier-lock.sqlite 连接持有 EXCLUSIVE 事务，应用整个生命周期持有；所有服务入口先取得锁，再扫描、迁移或更新中断任务。锁以数据库实际占用为准，不通过锁文件存在、PID 或过期时间判断，避免陈旧锁及 PID 复用误判。关闭时先停止新请求、等待写入和子任务，再释放锁。业务数据库不承担长时间独占事务。
2. **数据与格式。** 业务库使用 WAL、foreign_keys=ON、synchronous=FULL 和有界 busy_timeout。元数据初期采用按 bucket/id 存储原 JSON body 的兼容适配，保留 ID、业务版本、历史和解析 schemaVersion；关联与文件待办拥有明确事务边界。异步业务处理放在事务外，最终提交校验版本，事务回调不跨 await 持锁。
3. **原文件待办。** 元数据删除标记、主题关联清理、任务状态和文件待办同一事务提交；unlink／替换在提交后执行。待办带稳定操作 ID、相对路径、预期内容哈希、状态及错误；路径和内容验证通过才操作，缺失文件仅对匹配的删除待办视为幂等完成。写入／替换先落暂存文件、校验并 fsync，再发布；重启恢复时解释每个半完成状态。D2 才开放用户删除入口。
4. **备份屏障。** 持有目录锁，停止新写入，等待活动写入和文件操作结束；确认数据库完整性后取得一致数据库快照并复制引用的不可变原文件。记录格式版本、应用版本、文件大小与 SHA-256。使用独立暂存目录，全部校验、同步完成后才发布备份；不复制活动 WAL 主文件冒充备份。目录锁之外仍须有进程内屏障。
5. **迁移。** 旧 JSON 显式识别为旧格式；先保全原始目录并完成可还原备份，再将记录导入暂存库，验证数量、引用和证据身份，最后发布新 manifest。记录迁移批次并支持中断恢复；未完成时继续保留旧目录，不双写两套存储。损坏记录隔离必须可见，不悄悄跳过。
6. **恢复与降级。** 恢复到新目录，校验数据库及所有原文件后切换；现有目录完整保留。ZIP 拒绝路径逃逸、符号链接及超限展开；普通备份排除凭据。未知新格式在任务状态更新前拒绝写入，降级从兼容备份恢复到新目录。
