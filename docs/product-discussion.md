# 产品问题与讨论节奏

更新：2026-10-19。用户希望在继续开发的同时沟通产品问题。**从现在开始同步讨论，不等 D1–D5 全部做完。** 本文件记录待讨论场景和后续决定；它不替代已确认的产品框架，也不把工程实现当成用户已确认的产品方案。

## 如何推进

- 用户可以随时给出一个实际操作场景、遇到的问题和希望得到的结果，不要求先写完整需求。
- 影响当前主流程、数据含义或下一阶段交互的问题，先澄清结果与取舍，再做相关实现。确定不受影响的数据安全和自动化工作继续推进。
- 每个问题记录为：场景 → 当前表现 → 期望结果 → 可选处理 → 决定及验收方式。未确认的建议保留“待讨论”，不直接写成承诺。
- 影响删除、恢复、引用和历史保留的决定，在 D2 对应功能实现前讨论；模型配置／发送告知在 D3 界面前讨论；研究总结质量和导出使用方式现在即可讨论，在 D4 验收前明确。
- 每完成一个可操作的功能，结合真实任务检查结果；发现使用流程需要调整时，更新工作清单，而不是只等最后发布验收。

## 即将影响实现的场景（待讨论）

以下是工程推进到该阶段时需要核对的场景，**不是用户已经提出的问题，也没有预设答案**。用户实际反馈优先。

| 场景 | 需要明确的结果 | 处理时点 |
| --- | --- | --- |
| 一篇文献同时用于多个主题，用户想整理或删除它 | 移出当前主题、删除原文件、清除相关内容分别意味着什么；哪些笔记／引用／历史继续保留 | D2 删除入口设计前 |

| 用户把研究成果拿到工作台之外继续使用 | 需要什么结构、引用格式、编辑和导出体验；哪些质量问题最影响实际使用 | 现在可讨论，D4 前明确 |

## 用户问题记录

### UX-01：笔记和表单的输入负担（2026-10-19）

**用户反馈**：“产品在很多笔记、内容填写、表单填写里存在大量的内容输入……太冗余，太多了些。” 问题已确认收到；以下改进方向是针对反馈的实现提案，不代表用户已逐项确认全部交互。

**实际场景与当前表现**：阅读中想留下一段原文或一个想法，却先看到分类、内容状态、判断类型；空笔记页预列六类“未记录”。文献筛选同时展示“与研究问题的关联”和“选择理由”，比较单元格同时展示内容、状态、判断类型、条件、可比性、理由及出处，成果按区块展示多个编辑控件。输入、选择和检查都在争夺用户注意力。

**期望方向**：先完成阅读、记录和写作，再按需要整理。上下文能够提供的归属、来源和已有内容不再要求重填；专业属性按需修改；不把空分类展示成必须补齐的清单。模型仍是可选辅助，不能用自动生成内容替代用户真实判断。

**现有能力需复用**：从原文／问答创建笔记已带入内容和出处；比较单元格已有复制笔记入口；新比较表和成果已继承主题研究问题。问题包含既有能力的可发现性与界面负担，不能把这些功能重复描述为新开发。

| 范围 | 处理与状态 | 验收／待讨论点 |
| --- | --- | --- |
| UX-01a 笔记 | 首轮可体验实现：内容置顶并直接聚焦；分类／状态／类型移到可展开区，折叠摘要仍显示当前分类和类型；分类清空回落到既有“主要发现”；引用选择器按需打开，已选出处仍可核对；列表只展示有内容的分类 | 普通笔记仅输入内容即可保存；原文笔记不需重选出处；特殊缺失状态可记录；草稿、旧来源快照、历史和冲突保护回归；实现验证不等于用户体验验收 |
| UX-01b 主题与文献信息 | 待讨论：研究问题是否允许稍后完善；书目信息以已有值和校对为主；筛选理由与关联说明是否合为一处 | 先核对历史数据展示、检索／模型所需上下文及字段语义，不静默删除字段或合并历史文本；尚未承诺自动识别全部书目信息 |
| UX-01c 比较 | 待讨论：优先带入现有笔记和出处，围绕差异与判断编辑；条件／可比性解释在需要时展开 | 缺少信息与不可比较仍须清晰可见；不能把空白自动当成一致、可比较或已有结论 |
| UX-01d 成果 | 2026-10-21 用户批准按建议构建，首轮实现页面式文稿编辑；研究问题与段落属性按需展开，引用可直接回查，支持移除撤销 | DOM／HTTP 验证引用和草稿保留；真实浏览器受启动环境阻止，视觉与用户试用尚未验收；见 [实施记录](ux-01d-implementation.md) |

本轮先落实 UX-01a；后续按主题／文献 → 比较 → 成果逐步检查输入负担，不把大范围数据语义调整混入笔记界面改动。D1 数据安全仍进行中，跨平台范围不变。验证结果在 [统一工作清单](work-items.md#产品体验改进) 记录。

### UX-02：AI 应实际承担整理与综合，而不止减少表单

2026-10-19 用户进一步反馈：“我们都是 AI 产品了，为什么感觉还是如此 low”，并要求检索类似产品。已完成 NotebookLM、Elicit、SciSpace、Consensus、腾讯 ima 的官方公开资料对标，见 [AI 研究产品对标](product-benchmark-2026-10-19.md)。尚未做付费账户同题实测。

用户已回复“可以，开始构建吧”。首轮现已实现：主题内默认选择未排除的文献 → 输入研究目标 → AI 建议维度并生成整份带出处的比较草稿 → 人工核对与采用 → 自动带入该比较表生成研究总结草稿 → 采用、修订与 Markdown 导出。生成前不要求用户填写笔记、逐格整理或重复选择总结材料。详细范围与测试见 [UX-02 实施记录](ux-02-implementation.md)。

补上桌面“模型连接”会话入口，避免只能通过开发配置使用 AI。当前连接不落盘，退出后需要重新连接；完整系统凭据、连接测试和授权撤销仍属 D3。比较页可以用后续要求重新生成整份草稿，不会静默替换已保存内容。

本轮是第一条可操作流程，不等于所有表单已经改造：成果阅读可直接查看带引用草稿，编辑仍沿用段落编辑器；自由对话筛选文献、仅修改指定段落／维度、连续文稿编辑和真实供应商质量验收尚未完成。UX-01b–d 后续应围绕实际研究任务继续减负。
