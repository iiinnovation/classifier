# 功能主线产品审查

日期：2026-10-29。审查对象：调整前的工作区源码，包含上一轮比较表单精简。以下保留审查时的问题与证据；用户随后授权的调整和当前验证结果见 [UX-03 实施记录](ux-03-mainline-implementation.md)。

## 结论

研究主题、阅读、笔记、比较和总结都有明确用途，现有功能能够串起研究任务。主要负担来自**入口与信息层级**：所有能力同时出现，维护操作与日常操作并列，解释数据机制的文字反复出现，结果却往往在页面下方。

最需要先处理的两个具体问题是：总结草稿可见时导出的是空的已保存正文；窄窗口下材料与辅助写作区域排在总结正文之前。随后应精简主题页和比较页，让用户优先看到当前结果和下一步操作。

建议保留现有研究能力，先改善默认展示、状态和衔接。复杂的条件、证据与版本能力应在需要时容易找到；真实来源异常、采用覆盖范围和模型发送对象仍需明确显示。

## 审查依据与范围

以“创建主题 → 导入／关联 → 阅读／记录 → AI 比较 → 查看证据／采用 → 生成总结／采用 → 编辑／导出 → 返回继续研究”为主线，补查手工比较、手工成果、全部文献、模型设置、删除预览和存储用量。

真实 Chrome 渲染走查覆盖 **32 个状态**，包括 1440×1000 和 390×844 视口、0／1／2／8／13 篇主题文献。使用独立临时资料库、合成文献和进程内模拟模型；没有调用真实模型供应商或读写用户资料。截图、页面文字、按钮和纵向位置保存在 [observations.json](measurements/product-mainline-2026-10-29/observations.json)，走查脚本为 [audit.mjs](measurements/product-mainline-2026-10-29/audit.mjs)。

32 次快照均未发现页面横向溢出，走查未捕获前端脚本异常。**这不等于体验通过**：内容仍可能离首屏很远，比较表内部仍需横向滚动。脚本断言用于确认抵达相应状态，并非完整业务回归或真实研究质量验收。本轮未重新打包、重跑 OCR 或验证桌面资料库恢复；这些边界结合源码和既有测试审阅。

下列脚本对应调整前界面，只有匹配原始源码快照时才能重放。当前源码的走查请使用 [调整后脚本](measurements/mainline-adjustments-2026-10-29/walkthrough/audit.mjs)，避免覆盖原始对照证据：

```sh
node docs/measurements/product-mainline-2026-10-29/audit.mjs
```

脚本需要本机 Chrome 和本地监听权限，重跑会更新同目录证据并清理它创建的临时资料库。应用文件与本轮产物哈希见 [manifest.json](measurements/product-mainline-2026-10-29/manifest.json)。

## 主线逐项判断

| 环节 | 当前判断 | 应保留与应调整 |
| --- | --- | --- |
| 首页／创建主题 | 基本清楚 | 只填标题即可创建值得保留；首页标题、介绍和空状态可进一步合并 |
| 导入／关联 | 基本清楚 | 主题上下文自动带入、识别设置收起合理；统一“导入文档／导入文献”，注明 Word 实际支持 .docx |
| 主题概览 | 优先调整 | 同时承担任务输入、文献管理、比较、总结、笔记目录，已有成果被文献列表推到下方 |
| 筛选／阅读记录 | 已明显减负 | 状态可独立保存合理；卡片常驻长说明和全部操作仍重，批量整理效率后续观察 |
| 原文阅读／问答 | 核心结构合理 | 原文与问答并排、引用定位合理；未配置模型时的重复模式提示和通用合同示例需改 |
| 阅读笔记 | 编辑已较轻，入口有断点 | 内容优先、分类收起、有内容才显示分类合理；全部文献中不能直接进入记录流程 |
| 手工比较 | 必要的补充路径 | 维度可删至一项、内容带入、条件按需填写合理；常规用户不应先处理完整空矩阵 |
| AI 比较／后续调整 | 需要重新分层 | 草稿与旧空矩阵同时显示，整份／单列生成并列，继续研究输入抢在结果前 |
| 证据核对 | 能力必要，操作可压缩 | 保留摘录、来源状态与原文跳转；单个出处可直接打开摘录，核对按钮集中到证据处 |
| 总结阅读／采用 | 优先调整 | 可见草稿与已保存正文的编辑／导出状态不一致；窄窗口正文顺序错误 |
| 总结编辑／材料更新 | 编辑改善有效 | 文稿式输入和段落设置收起合理；首次手工写作、材料选择、更新版本的路径仍绕 |
| 历史／归档／维护 | 应低频可达 | 保留能力与数据语义；常驻按钮、诊断数字、空分组和长解释应减少 |

### PM-01：看到的草稿与导出的内容不一致

**复现**：从已采用的比较表生成总结，页面显示两段有引用的草稿，顶部仍显示“版本 1 · 0 个段落”。此时“编辑正文”和“导出 Markdown”均可点。点击导出，实际文件只有标题、问题和材料清单，没有画面里的两段正文。

证据：[总结草稿页面](measurements/product-mainline-2026-10-29/13-report-draft.png)、[实际导出文件](measurements/product-mainline-2026-10-29/13-export-before-adoption.md)。依据：[reports.js](../apps/web/reports.js#L111) 的空正文草稿预览与 [导出处理](../apps/web/reports.js#L461) 分别使用建议结果和已保存 report；[report-export.mjs](../apps/api/src/report-export.mjs#L5) 只导出已保存 blocks。

**建议**：尚无保存正文时，突出“采用总结”，空正文的编辑／导出入口改为对应引导；已有正文且有新草稿时，清楚区分“已保存正文”和“待采用草稿”，导出说明它使用哪一份。不要通过导出偷偷采用草稿。

**验收**：生成中的空成果、初次草稿、已采用成果、已有正文的新草稿四种状态，用户都能判断编辑和导出对象；有正文时实际导出与所指版本一致；采用和历史保护继续有效。

### PM-02：窄窗口下正文排在辅助区域之后

**复现**：390×844 下打开已采用总结，先出现标题、4 个操作、版本、所选材料、证据、材料加入正文和辅助写作。第一段正文标题在 y=940，已在首屏之外。

证据：[窄窗口总结](measurements/product-mainline-2026-10-29/24-report-narrow.png)。依据：[style.css](../apps/web/style.css#L360) 在 850 px 以下给 `.report-sidebar` 设置 `grid-row: 1`。

**建议**：窄窗口先展示正文；材料压成“材料 1 项 · 查看”并可展开；重新生成只在需要调整时展开。桌面也应让材料区服务于正文阅读。

**验收**：采用后的正常总结在 390×844 第一屏能看到正文开始；材料、旧出处、生成、版本和导出仍可达；出现来源变化时，警示在受影响正文附近仍清楚可见。

### PM-03／04：主题概览被文献管理占满

**复现**：8 篇主题文献时，研究成果区在 y=2557。每篇文献包括标题按钮、打开研读、书目信息、删除影响、筛选与阅读记录、移出主题、移出影响，共 7 个入口；标题和“打开研读”执行相同动作。

证据：[8 篇主题](measurements/product-mainline-2026-10-29/21a-topic-eight.png)、[13 篇主题](measurements/product-mainline-2026-10-29/21-topic-thirteen.png)。依据：[index.html](../apps/web/index.html#L31) 的主题区顺序和 [research.js](../apps/web/research.js#L53) 的卡片动作。

**建议**：主题顶部提供“文献／比较／总结／笔记”的明确导航与数量；在概览里保留最近工作入口。文献卡片以标题、书目摘要、两个状态和必要操作为主，书目信息、移出、删除放“更多”。移出／删除在被选中后展示对应影响，不常驻两套入口。说明文字有内容时显示简短摘要，可展开阅读全文。

**验收**：8–13 篇时，第一屏可进入已有比较／总结，不依赖滚过全部卡片；单卡片常驻操作建议不超过 3 个。标题研读与状态记录仍直接可达，删除影响与共享文献保护不减少。

### PM-05：比较页同时承载多个工作阶段

**复现**：AI 已生成 2 个维度的草稿，下面仍出现创建时默认 4 个维度的空矩阵、4 份空综合判断和逐列建议。用户需要分清两个表分别是什么。已采用后，继续研究输入仍排在比较结果上方。

证据：[双表页面](measurements/product-mainline-2026-10-29/09-comparison-draft.png)、[已保存比较](measurements/product-mainline-2026-10-29/10-comparison-saved.png)。依据：[comparisons.js](../apps/web/comparisons.js#L195) 始终展示 `comparison-saved`，同时 [renderTaskResult](../apps/web/comparisons.js#L517) 渲染草稿；[index.html](../apps/web/index.html#L61) 将继续研究放在结果前。

**建议**：用清楚的阶段组织同一页面：正在生成时显示进度；待采用时默认显示草稿，提供“查看／编辑已保存表格”；采用后默认显示当前比较结果和“生成总结”。继续研究输入收起为“调整要求”，逐列建议在相应维度的操作中可达。手工创建的表仍直接可编辑。

之前为了恢复手工入口而保留空矩阵是有依据的；本次精简必须提供明确入口，不能简单隐藏之后让用户无处编辑或放弃草稿。

**验收**：每个状态能辨认当前表与草稿；默认不出现两套矩阵和空综合判断；手工、放弃草稿、生成中编辑、来源冲突、采用后历史和单列调整仍可用。

### PM-06：记录笔记在主题归属处中断

**复现**：从全部文献打开一篇没有当前主题上下文的文献，阅读笔记显示两段说明并禁用“写笔记”。原文旁却仍有“记入笔记”，点击后只能得到“请从已关联的研究主题中创建笔记”。

证据：[全部文献阅读](measurements/product-mainline-2026-10-29/17-library-reader-notes.png)。依据：[notes.js](../apps/web/notes.js#L57)、[ensureContext](../apps/web/notes.js#L200)。当前实现按主题保存笔记的语义合理，断点是缺少就地补齐归属的交互。

**建议**：点击记入笔记时，若缺少主题上下文，就地选择一个已有主题或创建主题，关联文献后继续本次记录。已有多个主题时由用户选择，不自动猜测。原文片段和当前输入应保留。

**验收**：从全部文献开始也能连续保存带出处笔记，不必退回首页重新找文献；主题归属明确，同一文献的不同主题笔记不会混在一起。

## 建议的默认主线

主题首页要回答三个问题：有哪些材料、上次做到哪里、接下来可以做什么。保留研究问题简短摘要；已有比较与总结可在顶部直接打开。材料不足时先导入／阅读，材料与模型就绪时再突出 AI 整理。

比较页先回答“这些研究有什么共同点和差异”。默认阅读当前结果，出处紧邻内容；调整要求和高级属性按需打开。完成比较后，“生成总结”是清楚的下一步，手工编辑仍可直接找到。

总结页先回答“我要带走的文字是什么”。正文优先，草稿、保存状态、编辑和导出对象一致。材料、重新生成、历史与归档服务于修订，不抢占正文。

这是一套显示和操作层级的建议，不需要新增另一套研究工作流、任务中心或额外的“简易／专业”模式。

## 文案精简示例

| 位置 | 当前 | 建议 |
| --- | --- | --- |
| 主题 AI 区 | 让 AI 整理这些文献；说出研究目标，得到带出处的比较草稿，再继续形成研究总结 | 标题“比较文献”；输入标签“这次想比较什么？”；按钮“生成比较草稿” |
| 发送提示 | 选择 2–12 篇文献。开始后会将相关节选和笔记发送至已配置的模型；AI 建议比较维度并逐项取证 | “将所选文献节选与笔记发送至［服务名］。”数量在选择摘要中显示，取证机制进详情 |
| 未配置模型 | 尚未配置模型，仍可使用下方的阅读、笔记和手工比较 | “连接模型后可生成比较草稿。”配就地“连接模型”入口；阅读操作保持可达 |
| 已采用比较 | 比较草稿已采用，可直接修订、核对出处，再生成研究总结 | “比较已保存。”配“生成总结”；有未核对项时单独显示其数量 |
| 后续要求示例 | 增加样本量，重点比较研究局限 | “增加样本量这一维度，重点比较研究局限” |
| 筛选说明 | 只更新状态即可保存，说明可以在阅读后补充 | 字段写“筛选说明（可选）”，保留已有说明摘要即可 |
| 内容保存 | 当前标签页的未保存编辑 | “有未保存草稿”，具体草稿归属在恢复选择中说明 |
| 模型连接成功 | 本次运行已连接模型……尚未验证连接 | “模型配置已保存，连接尚未验证。” |
| 原文版本变化 | 原文版本已变化或无法确认，下面保留的是保存时的证据 | “原文已更新，当前显示旧摘录。请重新核对。”无法确认时另给对应状态，不能混称更新 |

正常说明可缩短，但不能把“未找到”写成“未报告”，不能将模型草稿说成已核验结论，也不能将引用身份有效等同于内容正确。

## 实施顺序与改后验收

| 批次 | 范围 | 完成标准 |
| --- | --- | --- |
| 第一批：结果与入口 | PM-01–06；优先导出状态、窄窗口正文、主题顶部成果入口、卡片动作、比较页阶段、就地笔记归属 | 看到的结果与操作对象一致；8–13 篇时成果可直接进入；当前默认结果只有一套；阅读到记录不中断 |
| 第二批：状态与文案 | PM-07–10、12–16 | 各阻止状态给出具体下一步；当前草稿入口不重复；正常状态和文案减少；必要异常、发送与采用信息仍明确 |
| 第三批：手工写作起点 | PM-11；在真实试用中观察是否还需要批量筛选与更深编辑 | 首次能开始正文；材料更新不覆盖旧引用；原段落归属与历史保留 |

改后应验证真实浏览器中的完整研究链、无模型手工链、单／多出处核对、草稿采用前后导出、390×844 正文顺序、8–13 篇导航、来源变化、刷新恢复及编辑冲突。上一轮比较单元格少填后保存／恢复的用例继续保留。应增加的自动化主要是上述结果错误和状态边界，纯文案调整以走查为主。

首轮真实试用建议仍按既定方案使用 5–10 篇材料，记录完成时间、回退找入口次数、核对出处次数与修订量。本轮可以判断信息层级有问题；不能据合成模型的重复输出评价真实总结质量，也不能据 UI 走查宣布科研任务效果已通过。
