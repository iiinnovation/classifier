## 操作路径

桌面应用菜单栏新增“资料库”：

1. **检查当前资料库**：先提示保存编辑和暂停任务；关闭业务后端取得目录锁，在独立 utility 进程检查；展示前 20 条问题，可保存最多 1000 条的完整检查清单。
2. **创建目录备份**：通过系统目录选择器选择存放位置，自动创建新的 UUID 备份目录，按已有一致快照／SHA-256 规则验证。原目录保留。
3. **从目录备份恢复**：选择含 `backup-manifest.json` 的目录并确认恢复含义；先验证备份，再停止当前后端，创建当前库的安全备份，恢复到应用用户目录 `libraries/<uuid>`，检查并启动新库，最后保存资料库位置。
4. **打开已有资料库**：检查目标，备份当前库，然后切换。可用于重新打开保留的原库，或使用离线迁移工具已完成的 SQLite 库。未知格式、不完整迁移、不安全路径或检查错误会阻止切换。
5. **升级当前 JSON 资料库**：显式执行检查、旧库备份和 SQLite 迁移，完成目标检查与启动后再切换；JSON 来源继续保留。
6. **查看迁移进度或继续迁移**：选择 `libraries` 下的迁移暂存目录或已发布目录，显示固定备份时点、记录／文件进度和目标。继续时先备份当前库，再按同一批次续跑；不会把中断后新修改合并进迁移结果。
7. **导出 ZIP 备份**：选择新文件名，创建验证后的快照并流式压缩，完整校验 ZIP 后独占发布，不覆盖已有目标。
8. **从 ZIP 备份恢复**：选择归档，先校验 ZIP，再备份当前库并恢复到新目录；使用与目录恢复相同的目标检查、启动、选择记录和失败回退。格式与空间要求见 [ZIP 说明](d1-zip-backup.md)。
9. **保全当前资料原件**：在数据库损坏或启动失败时复制当前目录中可读文件、数据库及辅助文件；副本可能仍含损坏内容，不作为正常备份使用。
10. **选择性恢复损坏资料**：预览备份与中断写入候选，逐项选择后恢复到新目录；当前库、跳过的异常资料和恢复前的较新修改都保留。
11. **从升级前备份重新准备迁移**：准备阶段未建立完整进度表时，保留旧暂存目录，从固定 JSON 备份创建新批次；切换前另行备份当前库的较新修改。

当前库切换前的备份位于用户目录 `library-backups/<uuid>`，成功提示包含路径。恢复副本没有备份时点之后的新修改；原库和切换前备份都保留。切换及恢复不覆盖原库，也不自动合并内容。

维护会中止在途生成／导入任务，随后重新启动后端；会话模型连接需重新填写。原有草稿沿用输入时保存机制，执行前仍提示用户保存编辑。资料库路径按真实目录确定存储命名空间，恢复副本不会读取同 ID 的原库草稿或导航；默认资料库保留旧命名空间，重新打开时可恢复其草稿。

若业务后端启动失败，错误对话框提供检查清单、原件保全及“从兼容备份恢复”。核验备份时点和格式、确认后保全当前原件，恢复并启动新库后才保存位置；操作失败仍保留原位置，可继续选择其他备份或退出。见 [兼容恢复与准备重建](d1-compatibility-recovery.md)。若检查成功但服务重启失败，仍保留并显示检查结果。

## 失败与进程边界

- 整个维护过程串行；菜单不允许并发操作，退出等待在途维护结束。重启为维护的预期退出，不显示意外断开提示。
- 路径只由主进程系统选择器取得，没有新增渲染页面文件系统 IPC。计算及大文件复制在独立维护进程执行。
- 后端停止并释放目录锁后才执行离线维护；新库启动前再次依赖生产目录锁和格式检查。
- 目标启动失败或资料库位置写入失败时停止目标后端并重启原库；原库也无法重启时明确报告两次失败，不切换为空库。
- 位置记录通过临时文件、文件同步和重命名保存；位置文件缺失沿用旧默认目录，位置记录损坏或目标不可用会拒绝启动，不自动创建替代目录。尚未验收真实断电的目录项持久化。
- 迁移先由生产准备流程生成并校验 JSON 备份，再创建新 SQLite 暂存库；生产续跑以原备份清单哈希和进度事务校验，不改写 JSON 来源。完成目标启动失败或切换位置写入失败时，完成的新库保留，重新选择批次会命中已完成检查并再次尝试切换。
- 切换期间协议桥阻止旧窗口访问新后端；创建新窗口后先销毁旧渲染页面，再为新库加载页面，避免旧轮询／写入访问新库。
